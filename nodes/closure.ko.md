# 클로저

## 요약

클로저(closure)는 두 가지 언어 기능이 결합될 때 생기는 것이다: 함수를 값으로 다룰 수 있는 것([[first-class-function]])과, 이름이 코드가 작성된 위치를 기준으로 해석되는 것([[lexical-scoping]])이다. 클로저는 함수가 사용하는 주변 변수들의 스냅샷 — 그 함수가 **포획한 환경(captured environment)** — 과 함께 묶인 함수로서, 나중에 그 함수가 호출될 때 — 심지어 그것을 만든 코드가 이미 끝난 한참 뒤라도 — 여전히 그 변수들을 볼 수 있게 해준다. 다시 말해 클로저는 **코드와 그 코드가 닫아 포함한(closed over) 환경**이다. 이 덕분에 다른 함수로부터 반환된 함수가 계속 동작할 수 있다: 보통이라면 바깥 함수가 반환될 때 사라져야 할 그 지역 변수들이, 반환된 함수가 그것들을 포획했기 때문에 계속 살아 있는 것이다. 클로저는 객체나 클래스 없이도 함수에 부착된 사적이고 지속적인 상태 — 카운터, 설정된 콜백, 제너레이터 — 를 가능하게 한다.

## 상세 설명

**왜 두 전제조건이 결합해 새로운 것을 만드는가.** [[first-class-function]]만 놓고 보면: 다른 함수 안에서 함수를 만들어 값으로 반환할 수 있다. [[lexical-scoping]]만 놓고 보면: 함수의 자유 이름(함수가 사용하지만 선언하지 않은 이름)은 그 함수가 *작성된* 둘러싼 텍스트 안의 바인딩을 가리킨다. 이 둘을 합치면 긴장이 생긴다. 바깥 함수가 지역 변수를 선언하고, 그 변수를 언급하는 안쪽 함수를 반환한다고 하자. [[lexical-scoping]]에 따르면 안쪽 함수가 그 이름을 사용하는 것은 바깥 함수의 지역 변수를 가리킨다. 그러나 일반적인 실행 방식에 따르면, 바깥 함수가 반환되는 순간 그 지역 변수들은 사라진다. [[lexical-scoping]]을 문자 그대로 지킨다면, 반환된 함수는 더 이상 존재하지 않는 변수를 가리키게 될 것이다.

**해법 — 포획.** 클로저는 참조된 바깥 변수들을 **포획(capture)**함으로써 이 긴장을 해소한다: 함수 값이 자신이 필요로 하는 자유 이름들의 바인딩을 함께 가지고 다니면서, 함수 자신이 살아 있는 한 그 바인딩들도 계속 살려둔다. 그러므로 클로저는 함수의 코드만이 아니라 — 코드 *더하기* 포획된 변수들의 환경(흔히 *업밸류(upvalue)*라 불린다)에 대한 참조이다. 여기서 두 가지 사실이 따라 나오는데, 이것이 핵심 전부다. 첫째, 포획된 변수들은 그것들을 만든 스코프보다 *더 오래* 산다. 클로저가 그것들을 붙잡고 있기 때문이다. 둘째, 포획된 변수들은 진짜로 *같은* 변수이지 복사본이 아니다 — 클로저가 그중 하나를 변경하면 그 변경은 호출들 사이에서 지속되며, 이것이 함수에 사적 상태를 부여한다. 여러 클로저가 *같은* 환경을 포획한다면, 그것들은 그 상태를 공유한다.

**구체적인 예시.** 카운터 팩토리:

```
function makeCounter()
  local n = 0                       -- a local of makeCounter
  return function()                 -- a first-class function value, returned
    n = n + 1                       -- free name n → makeCounter's local (lexical)
    return n
  end
end

c = makeCounter()   -- makeCounter has RETURNED; its n survives inside the closure c
c()                 -- 1
c()                 -- 2
c()                 -- 3

c2 = makeCounter()  -- a fresh call → a fresh n, a separate captured environment
c2()                -- 1   (not 4!)
c()                 -- 4   (c's own n continued)
```

[[lexical-scoping]]에 따라 안쪽 함수의 `n`은 `makeCounter`의 지역 변수이다. 안쪽 함수는 [[first-class-function|일급]]이기 때문에 반환되어 `c`에 저장된다. 클로저는 `makeCounter`가 반환된 뒤에도 `n`을 살려두므로, `c`를 잇달아 호출하면 *같은* `n`이 증가하는 것을 본다: `1, 2, 3`. 정말 핵심적인 부분은 `c2`이다: `makeCounter`를 두 번째로 호출하면 *다른* `n`을 포획한 클로저가 생기므로, `c2()`는 다시 `1`부터 시작하고 `c`는 독립적으로 `4`로 이어간다. 두 개의 클로저, 두 개의 사적 환경 — 클로저가 하나의 전역 변수를 공유하는 것이 아니라 자기만의 환경을 포획한다는 것을 보여주는 명백한 증거다.
