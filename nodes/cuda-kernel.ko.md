# CUDA 커널

## 요약

CUDA 커널은 **한 번만** 작성하지만 GPU 실행의 **모든** 스레드가 **병렬로** 실행하는 함수다. 이것은 서로 연결된 두 개의 절반으로 구성된다. 첫 번째는 *커널 함수*다: [[cuda-thread-hierarchy]]의 그 스레드의 인덱스로 표현된, **한** 스레드가 하는 일을 기술하는 GPU 코드 조각(CUDA C++에서는 `__global__` 한정자로 표시된다). 두 번째는 *실행(launch)*이다: `kernel<<<grid, block>>>(args)`로 작성되는 CPU 코드 한 줄로, **몇 개의** 스레드를 생성할지 — 그리드는 몇 개의 블록으로, 각 블록은 몇 개의 스레드로 — 를 지정하고 그 함수를 실행하는 모든 스레드를 시작시킨다. 커널이 강제하는 사고의 전환은 이것이다: 데이터에 대한 루프를 **작성하지 않는다.** 단일 원소에 대한 본문을 작성하고, *원소당 하나의 스레드*를 실행한다. 각 스레드가 자신의 인덱스를 계산할 수 있으므로, 각자가 자신의 원소를 골라내고, CPU에서라면 작성했을 루프는 단순히 사라진다.

## 상세 설명

**개념이 무엇인가.** 평범한 CPU에서 길이 `n`인 두 배열을 더하려면 루프를 작성한다: 하나의 워커가 `i = 0, 1, 2, …, n-1`을 걸어가며, 각 단계에서 `out[i] = a[i] + b[i]`를 계산한다. 루프는 *명시적*이다: 워커 하나, `n`번의 반복, 순차적으로 완료. CUDA 커널은 이것을 완전히 다른 방식으로 대체한다. [[cuda-thread-hierarchy]]로부터 우리는 이미 GPU 실행이 블록으로, 그리고 그리드로 조직된 방대한 스레드 집합을 만들어내며, **각 스레드가 그 집합에서 자신이 어느 슬롯인지 알기 위해 읽을 수 있는 인덱스를 가지고 있다**는 것을 알고 있다. 커널은 정확히 이것을 활용한다: 전체 `n`개 원소를 순회하는 워커 하나 대신, `n`개의 워커를 생성하고 각각에게 자신의 인덱스로 선택된 단일 원소를 맡긴다. 커널은 (a) 하나의 워커의 작업을 기술하는 함수와 (b) 몇 명의 워커를 만들지 지정하는 실행의 짝 *그 자체*다.

**두 절반, 이름 붙이기.** GPU를 위한 CUDA 프로그램은 서로 다른 두 칩에서 실행되는 두 개의 코드 조각을 가지며, 커널 개념은 이 둘 모두에 걸쳐 있다:

- **커널 함수**는 GPU 코드다 — 각 스레드에서 실행되는 본문이다. CUDA C++에서는 `__global__` 한정자로 표시되며, 이는 컴파일러에게 "이 함수는 *CPU에서 호출되지만 GPU에서 실행된다*"고 알려준다. (그 형제 한정자인 `__device__`는 GPU에서 호출되고 GPU에서 실행되는 헬퍼를 표시하고, `__host__`는 평범한 CPU 코드, 즉 기본값을 표시한다.) 결정적인 속성은: 커널 함수는 *하나의* 스레드를 위해 작성된다는 것이다. 데이터에 대한 루프를 포함하지 않으며, 자신과 함께 몇 개의 스레드가 실행되었는지조차 모른다 — 오직 자신의 인덱스만 안다.
- **실행**은 몇 개의 스레드를 생성할지 결정하고 그것들을 시작시키는 CPU 코드다. 문법은 `kernel<<<grid, block>>>(args)`로, `block`은 각 블록에 몇 개의 스레드가 들어가는지, `grid`는 실행을 구성하는 블록이 몇 개인지 — 정확히 [[cuda-thread-hierarchy]]의 그 두 단계 구조다. `args`는 평범한 함수 인자들(데이터에 대한 포인터, 길이 등)이다. *분배*에 관한 모든 결정 — 몇 개의 블록, 각각 몇 개의 스레드 — 은 여기 실행 안에 살며, 커널 함수 안에는 결코 살지 않는다.

**왜 이렇게 나누는가(핵심 통찰).** 이 분리는 **하나의 작업 단위가 무엇인지**와 **그것을 얼마나 많이 실행할지**를 깔끔하게 분리한다. 커널 함수는 *무엇을*을 고정한다: "내 원소가 주어지면, 이것을 계산하라." 실행은 *얼마나 많이*를 고정한다: "이만큼의 스레드를 만들어라." 이것이 두 가지 이유로 강력하다. 첫째, 커널 함수를 전혀 건드리지 않고 오직 실행 숫자만 바꿔서 병렬성의 양을 바꿀 수 있다 — 같은 계산을 천 개의 원소에 대해서든 십억 개에 대해서든 실행할 수 있다. 커널을 튜닝하는 것은 대개 본문을 재작성하는 것이 아니라 실행 매개변수를 조정하는 것을 의미한다. 둘째, 이것은 하드웨어와 맞아떨어진다. GPU는 많은 독립적인 처리 유닛들(각각을 [[streaming-multiprocessor]], 즉 SM이라고 부른다)로 만들어져 있다. 실행은 GPU에 블록들의 그리드를 건네고, 하드웨어는 그 블록들을 자신의 SM들에 분배해 동시에 실행한다. 분배의 단위가 *블록*이고 실행이 블록을 만들어내는 것이므로, 실행이야말로 작업이 칩 위로 퍼지는 방식을 제어하는 바로 그 손잡이인 반면, 커널 함수는 한 스레드의 산술에 대한 순수한 기술로 남는다.

**"루프가 사라진다."** 이것은 커널을 작성하는 것에 대해 가장 혼란스럽고 가장 중요한 것이므로 직접적으로 언급할 가치가 있다. CPU에서는 반복을 손으로 작성한다: `for (i = 0; i < n; i++) out[i] = a[i] + b[i];`. 커널 함수에는 **루프가 없다.** 예전에 `for (i = 0; …)`였던 줄은 이 스레드 *자신의* `i`를 자신의 인덱스로부터 계산하는 단일 대입문이 되고, 그 뒤로 본문이 한 번 실행된다. CPU가 "워커 하나, `n`번의 반복"이었던 곳에서, GPU는 "`n`명의 워커, 각각 한 번의 반복"이다. 스레드의 그리드가 루프 그 자체가 *된다* — 반복 횟수 `n`은 이제 실행의 그리드 크기에 살고, 루프 변수 `i`는 이제 각 스레드의 인덱스다. 더 이상 연산의 시퀀스를 작성하는 것이 아니라, 한 스레드가 무엇을 하는지를 기술한 뒤 방대한 수의 그것을 실행하는 것이다.

**실전 사례 — 1,000,000개 원소에 대한 벡터 덧셈.** `a`, `b`, `c`가 GPU 메모리에 있는 `n = 1,000,000`개의 부동소수점 숫자 배열이고, 모든 `i`에 대해 `c[i] = a[i] + b[i]`를 원한다고 하자. 커널 함수(GPU 코드, `__global__`로 표시되고, 아무것도 반환하지 않음)는 다음과 같다:

```
__global__ void add(float* a, float* b, float* c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) c[i] = a[i] + b[i];
}
```

이것을 하나의 스레드의 스크립트로 읽어보자. 첫 줄은 [[cuda-thread-hierarchy]]의 표준적인 1D 인덱스 계산이다: `blockIdx.x`는 이 스레드가 어느 블록에 있는지, `blockDim.x`는 블록당 몇 개의 스레드가 있는지, `threadIdx.x`는 이 스레드가 자신의 블록 안에서 어느 위치에 있는지다 — 그래서 `blockIdx.x * blockDim.x + threadIdx.x`는 전체 그리드에 걸친 이 스레드의 고유한 위치다. 그 단일 숫자 `i`가 이 스레드가 소유하는 원소다. 둘째 줄은 *그 하나의* 원소에 대한 작업을 수행한다. 루프는 어디에도 보이지 않는다; 본문은 스레드당 정확히 한 번 실행된다.

이제 실행(CPU 코드)이다. 블록당 `256`개의 스레드를 선택한다 — 흔하고 하드웨어에 친화적인 블록 크기다. 1,000,000개의 원소를 커버하려면 몇 개의 블록이 필요한가? 최소 `1,000,000 / 256 = 3906.25`개의 블록이 필요하고, 블록의 분수를 실행할 수는 없으므로 **위로** 반올림하여 `3907`개의 블록으로 한다. 따라서 실행은 다음과 같다:

```
add<<<3907, 256>>>(a, b, c, n);
```

이것은 `3907 × 256 = 1,000,192`개의 스레드를 생성하며, 각각 자신의 `i`에 대해 `add` 함수를 실행한다. 그 개수에 주목하라: `1,000,000`개 원소에 대해 `1,000,192`개의 스레드 — `3907`개 블록이 `256`개씩이면 데이터를 살짝 넘치게 하므로 **192개의 여분** 스레드를 만든 것이다. 이것이 정확히 커널 함수에 `if (i < n)`이라는 줄이 있는 이유다. 인덱스 `1,000,000`부터 `1,000,191`까지의 `192`개 스레드는 이 가드가 없으면 배열의 끝을 지나쳐 쓰게 된다 — 범위를 벗어나 메모리를 손상시킨다. 가드는 이 초과 스레드들이 자신의 `i`를 계산하고, `i < n`이 거짓임을 발견하며, 조용히 아무것도 하지 않게 만든다. 나머지 `1,000,000`개 스레드는 각각 하나의 유효한 원소를 처리한다. 함께, 작은 함수 하나의 한 번의 실행이 백만 번 반복하는 CPU 루프를 대체하며, GPU는 그 백만 번의 덧셈을 하나씩 순서대로가 아니라 자신의 SM들에 걸쳐 병렬로 실행한다. `if (i < n)` 가드는 암기해야 할 특수한 경우가 아니다 — 그리드 크기가 정수 개의 블록으로 반올림된다는 것의 일반적인 결과이며, 그래서 실행은 데이터 길이의 정확한 배수에 거의 결코 맞아떨어지지 않는다.
