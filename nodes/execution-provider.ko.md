# 실행 공급자 (Execution Provider)

## 요약

**실행 공급자(execution provider)**는 런타임이 하드웨어별 백엔드에 모델의 어느 부분을
실행할 수 있는지 묻게 해 준다. 런타임은 공통 인터페이스를 통해 지원되는 하위 그래프를
그 공급자에게 할당하고, 지원되지 않는 작업은 다른 공급자에게 보낸다.

## 상세 설명

[[computation-graph]]의 각 노드는 [[operator-set]]이 정의한 연산을 호출한다. 하드웨어
백엔드는 그 연산, 자료형, 형상의 일부만 구현할 수 있다. 실행 공급자는 자신의 기능을
런타임에 알리고, 맡은 작업의 구현을 제공하며, 장치에 필요한 메모리를 관리한다. 런타임은
전체 모델과 공급자 경계를 넘는 값의 연결을 계속 책임진다.

공급자는 우선순위 순서로 검토된다. [[graph]]의 노드와 간선 연결을 이용해 첫 번째
공급자가 처리할 수 있는 가장 큰 영역을
가져가고 다음 공급자가 남은 부분을 검토한다. 기본 공급자는 마지막에 와서 대체 구현을
제공하므로 가속기가 모델 일부만 지원해도 전체 모델을 실행할 수 있다. 연결된 각 영역은
한 공급자가 소유하는 하위 그래프가 되며, 공급자는 노드를 하나씩 실행하거나 영역 전체를
특수 연산으로 컴파일할 수 있다.

**구체적인 예.** `MatMul → Add → Custom` 경로를 생각하자. 우선 가속기는 `MatMul`과
`Add`를 지원하지만 `Custom`은 지원하지 않는다고 보고하므로 앞의 두 노드를 하나의 하위
그래프로 가져간다. 기본 CPU 공급자는 `Custom`을 가져간다. 런타임은 가속기 하위 그래프를
실행하고, 이름이 붙은 출력을 공급자 경계 너머로 전달한 뒤, CPU에서 `Custom`을 실행한다.
공통 공급자 인터페이스가 없다면 애플리케이션은 백엔드마다 별도 스케줄링 코드를 작성해야
한다.
