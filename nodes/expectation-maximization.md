# Expectation-Maximization

## Summary

**Expectation-Maximization (EM)** is the way to compute a [[maximum-likelihood-estimation]] estimate when a *latent* variable — a hidden cause you never get to observe — makes the [[likelihood]] impossible to maximize directly. Recall that MLE picks the parameter $\theta$ under which the observed data is most probable, and that with *known* labels you find it by simple counting (a coin's bias is just heads-over-total). The trouble: when each datapoint was generated by one of several hidden sources but you are not told which, the likelihood of a datapoint becomes a *sum over every possible hidden assignment*, and the logarithm can no longer slide inside that sum to give a clean count — the tidy MLE recipe breaks. EM sidesteps this with a chicken-and-egg trick: if you knew the hidden labels you could do MLE, and if you knew $\theta$ you could *infer* the labels. So it alternates. The **E-step**, holding $\theta$ fixed, uses [[bayes-rule]] to compute each hidden source's **responsibility** for each datapoint — the posterior $P(\text{hidden}=c \mid \text{data}) \propto \pi_c\,P(\text{data}\mid c)$, a soft probabilistic guess at the missing label. The **M-step**, holding those responsibilities fixed, redoes [[maximum-likelihood-estimation]] using **fractional counts** weighted by the responsibilities — the soft-label version of the hard count you would do with known labels. Iterate, and a provable fact holds: each round cannot *decrease* the true likelihood, so EM climbs to a stationary point of the very same MLE objective it could not attack head-on. EM is, more precisely, an *algorithm*, not a fixed estimator: leave the M-step as plain MLE and it reaches the MLE; add a log-prior term to the M-step and the identical alternation instead reaches the **MAP** estimate (the MAP–EM variant below).

## Grounded explanation

### The problem: a latent variable breaks the MLE recipe

From [[maximum-likelihood-estimation]] we have a complete method when the model's structure is fully visible. We write the [[likelihood]] $L(\theta) = P(D \mid \theta)$ — the probability the model assigns to the observed data $D$ as a function of the parameter $\theta$ — take its logarithm $\ell(\theta) = \ln L(\theta)$ so the product over independent observations becomes a *sum* of logs, differentiate, and solve $\ell'(\theta)=0$. For a coin this whole chain collapses to a single number: $\hat p = h/(h+t)$, heads over total flips. The reason it stays simple is that the log of each observation's probability is one clean term, so counting heads is all that survives.

A **latent variable** is a quantity that genuinely participates in generating the data but that you never observe. The standard example: you have several different coins with different biases, you flip *one of them* to produce each batch of results, **but you are not told which coin was used.** The identity of the coin is the latent variable — call its value $z$ (the hidden "cause"), one of $C$ possible sources indexed $c = 1, \dots, C$.

Here is exactly where MLE jams. To write the probability of one observed datapoint $d$ you must account for the fact that *any* of the sources could have produced it. By the disjoint-addition rule, the probability of $d$ is the sum over which hidden source was responsible:

$$ P(d \mid \theta) = \sum_{c=1}^{C} \pi_c \, P(d \mid c, \theta), $$

where $\pi_c$ is the **prior** probability that source $c$ was the one selected (the mixing weight, with $\sum_c \pi_c = 1$) and $P(d \mid c, \theta)$ is the [[probability-distribution]] of source $c$ evaluated at $d$ — how that one source would have generated $d$. The log-likelihood of the whole dataset is then

$$ \ell(\theta) = \sum_{i=1}^{n} \ln\!\Big(\sum_{c=1}^{C} \pi_c\, P(d_i \mid c, \theta)\Big). $$

Now the log sits *outside a sum*. The trick that made MLE tractable — $\ln$ turning a product into separable terms — no longer reaches the individual sources, because $\ln(a + b)$ does not split into $\ln a + \ln b$. Differentiating this and solving for $\theta$ in closed form is generally impossible: every parameter is tangled with every other through that inner sum. The latent variable has converted a one-line count into an intractable optimization. **This — not some new estimation goal — is the entire reason EM exists.** EM targets the *same* maximum-likelihood $\hat\theta$; it only provides a route to it when the sum-inside-the-log blocks the direct path.

### The key idea: if you knew the hidden labels, MLE would be trivial again

Notice the source of the difficulty is solely the *missing* labels. Suppose a benefactor revealed, for every datapoint, exactly which source produced it. Then there is no sum: each datapoint belongs to one known source, the data partitions cleanly into $C$ groups, and you do an ordinary [[maximum-likelihood-estimation]] *within each group* — for coins, count heads-over-total using only the flips known to come from that coin. Trivial.

This exposes a chicken-and-egg structure:

- If we knew the parameters $\theta$, we could *infer* which source most likely produced each datapoint.
- If we knew which source produced each datapoint, we could *estimate* $\theta$ by plain MLE.

We know neither. EM breaks the deadlock by guessing one and refining the other, alternately, each step solving an easy sub-problem with the other quantity held fixed.

### The E-step: responsibilities are exactly Bayes' rule on the hidden label

Fix the current parameters $\theta$ (we will start them at a guess). For each datapoint we cannot know the true source, but we *can* compute the probability of each source **given the data we saw** — which is precisely a posterior over the latent variable, and precisely the job of [[bayes-rule]].

Set the unknown cause to be the source identity, $z = c$, and the evidence to be the observed datapoint $d_i$. Bayes' rule says posterior $\propto$ likelihood $\times$ prior:

$$ r_{c,i} \;=\; P(z = c \mid d_i, \theta) \;=\; \frac{\pi_c\, P(d_i \mid c, \theta)}{\sum_{c'=1}^{C} \pi_{c'}\, P(d_i \mid c', \theta)}. $$

The number $r_{c,i}$ is called the **responsibility** of source $c$ for datapoint $i$ — how much of the credit for generating $d_i$ source $c$ deserves, in light of the current $\theta$. The numerator is the prior $\pi_c$ (chance source $c$ was picked at all) times the likelihood $P(d_i\mid c,\theta)$ (how well source $c$ explains $d_i$); the denominator is the normalizer from [[bayes-rule]] — the sum of the numerator over all sources — which forces $\sum_c r_{c,i} = 1$ for each datapoint. So the responsibilities are a genuine probability distribution over "which source" for each point: a **soft label** in place of the missing hard one. A datapoint that source $c$ predicts far better than its rivals gets $r_{c,i}$ near $1$; an ambiguous datapoint gets its responsibility split.

This is the **E-step** (for *expectation*: the responsibilities are the [[expectation]]s — probability-weighted averages — of the hidden 0/1 "did source $c$ produce point $i$?" indicators under the current $\theta$).

### The M-step: MLE again, but with fractional counts

Now flip what is held fixed: freeze the responsibilities and re-estimate $\theta$. The move that makes EM work is to treat each responsibility as a **fractional membership**. Where the known-label MLE would count a datapoint *once* toward its one true source, we instead count it $r_{c,i}$ times toward source $c$ — a partial, weighted contribution. With those soft counts the intractable sum-inside-log dissolves back into the same clean per-source MLE we had with known labels; it is the identical maximization, with $1$'s replaced by fractions.

For coin biases this is concrete. The hard-label MLE for source $c$ is heads-over-total *among its flips*. The soft version weights every batch's heads and totals by that batch's responsibility:

$$ \theta_c \;=\; \frac{\sum_{i} r_{c,i}\,h_i}{\sum_{i} r_{c,i}\,(h_i + t_i)}, $$

where $h_i$ and $t_i$ are the heads and tails in batch $i$. The numerator is the expected number of heads attributable to coin $c$; the denominator is the expected number of flips attributable to coin $c$. Set $r_{c,i}$ to $0$ or $1$ (labels known) and this is exactly the ordinary MLE $\hat p = h/(h+t)$ restricted to coin $c$'s batches. The mixing weights update the same way: $\pi_c = \frac{1}{n}\sum_i r_{c,i}$, the average responsibility.

This is the **M-step** (for *maximization*: it is the MLE maximization, performed on soft counts).

### Why iterating works: it cannot decrease the likelihood

EM alternates E and M until $\theta$ stops moving. The non-obvious guarantee — the thing that makes this more than wishful alternation — is that **each full E-then-M round never decreases the true log-likelihood $\ell(\theta)$**, the same quantity from the intractable sum-inside-log we wanted to maximize all along. The E-step builds, from the current $\theta$, a *lower bound* on $\ell$ that touches it exactly at the current $\theta$ (the responsibilities are chosen to make the bound tight there); the M-step then maximizes that bound. Because the bound touches $\ell$ at the old $\theta$ and the M-step climbs the bound, the new $\theta$ must score at least as high on $\ell$ itself. A quantity that never decreases and is capped above (a likelihood is bounded) must settle — so EM converges to a **stationary point** of the likelihood. EM thus reaches an MLE solution by a staircase of guaranteed non-worsening steps, exactly when the direct $\ell'(\theta)=0$ attack was unavailable.

Two honest caveats follow from "stationary point." First, *stationary* need not mean *global* maximum — like the derivative condition in [[maximum-likelihood-estimation]], it can land on a local peak, so the starting guess matters. Second, there is a degenerate trap shown below.

### Worked instance: two coins, hidden which one was flipped

Two coins, $A$ and $B$, with unknown head-biases $\theta_A, \theta_B$. We run $5$ batches; each batch is $10$ flips of **one coin, but we are not told which.** The recorded head counts are

$$ \{\,5,\ 9,\ 8,\ 4,\ 7\,\} \quad(\text{so tails are } \{5,1,2,6,3\}). $$

The latent variable is the coin used in each batch. We assume each coin is equally likely to be chosen, $\pi_A = \pi_B = 0.5$. (Because these priors are equal, they cancel from the responsibility ratio — but they are genuinely *present*; with unequal coins they would not cancel, so this is not a degenerate omission.) We initialize with a deliberate asymmetry, $\theta_A = 0.6,\ \theta_B = 0.5$.

**One E-step.** Take the second batch, $h = 9$ heads, $t = 1$ tail. The likelihood that *coin $c$* produced it is $L_c = \theta_c^{\,h}(1-\theta_c)^{\,t}$ (its Bernoulli probability of $9$ heads and $1$ tail). With the current parameters:

$$ L_A = 0.6^{9}\,(0.4)^{1} = 4.03\times10^{-3}, \qquad L_B = 0.5^{9}\,(0.5)^{1} = 9.77\times10^{-4}. $$

By [[bayes-rule]], with the equal priors $0.5$ canceling top and bottom, the responsibility of coin $A$ for this batch is

$$ r_{A} = \frac{L_A}{L_A + L_B} = \frac{4.03\times10^{-3}}{4.03\times10^{-3} + 9.77\times10^{-4}} = 0.805, $$

and $r_B = 0.195$. The strongly-heads batch ($9/10$) is attributed mostly — but not entirely — to the more heads-biased coin $A$. Repeating for all five batches (head counts $5,9,8,4,7$) gives coin-$A$ responsibilities

$$ r_A = \{\,0.449,\ 0.805,\ 0.734,\ 0.352,\ 0.647\,\}. $$

Note the soft, non-degenerate split: the $5$-head batch is nearly a coin-flip of credit ($0.449$), the $4$-head batch tilts to $B$ ($0.352$), the heads-heavy batches tilt to $A$.

**One M-step.** Re-estimate $\theta_A$ from these soft counts via the fractional-count MLE. With every batch having $h_i + t_i = 10$ flips:

$$ \theta_A = \frac{\sum_i r_{A,i}\,h_i}{\sum_i r_{A,i}\cdot 10}. $$

The expected heads for $A$ is $0.449(5) + 0.805(9) + 0.734(8) + 0.352(4) + 0.647(7) = 2.247 + 7.245 + 5.868 + 1.409 + 4.530 = 21.30$, and the expected flips for $A$ is $(0.449+0.805+0.734+0.352+0.647)\times 10 = 2.987 \times 10 = 29.87$. So

$$ \theta_A = \frac{21.30}{29.87} = 0.713. $$

One E-then-M round has moved $\theta_A$ from $0.600$ to $0.713$ (and, symmetrically, $\theta_B$ from $0.500$ to $0.581$).

**The trajectory.** Iterating the same two steps, the parameters climb to a fixed point:

$$ \theta_A:\ 0.600 \to 0.713 \to 0.745 \to 0.768 \to 0.783 \to \cdots \to 0.797, $$
$$ \theta_B:\ 0.500 \to 0.581 \to 0.569 \to 0.549 \to \cdots \to 0.520. $$

And the diagnostic that the theory promised: the true log-likelihood $\ell$ rises *every* round — $-33.09 \to -31.86 \to -31.72 \to -31.63 \to \cdots$ — never once decreasing, confirming the monotone-ascent guarantee in this concrete run. EM has produced a maximum-likelihood estimate of the two hidden biases despite never seeing a single coin label.

**The symmetric-start pitfall.** Suppose instead we had initialized $\theta_A = \theta_B$. Then for *every* batch $L_A = L_B$, so every responsibility is frozen at $r_A = r_B = 0.5$; both M-step updates produce the *same* new value, the two coins stay identical, and the responsibilities stay $0.5$ forever. EM is stuck. This is a **saddle** — a stationary point of the likelihood that is not the maximum — and it is exactly why the worked run used the asymmetric start $0.6 \neq 0.5$. The symmetry must be broken for the two sources to differentiate; this is the practical face of the "stationary point need not be the global maximum" caveat above.

### The MAP–EM variant: a log-prior in the M-step reaches the MAP instead

Everything above climbs the likelihood, so its fixed point is the MLE. But the M-step is just an internal [[maximum-likelihood-estimation]] on soft counts, and that internal objective is the only thing tying EM to the MLE — change it and the destination changes with it. If we hold a prior belief $P(\theta)$ over the parameters, the quantity we now want to maximize is the posterior $P(\theta \mid D) \propto P(D \mid \theta)\,P(\theta)$, whose log adds a log-prior term to the log-likelihood. So we make the M-step maximize *expected log-likelihood plus log-prior* rather than expected log-likelihood alone — the soft-count objective gains one extra summand:

$$ \theta \;\leftarrow\; \arg\max_{\theta}\ \Big[\underbrace{\textstyle\sum_{i,c} r_{c,i}\,\ln P(d_i \mid c, \theta)}_{\text{expected log-likelihood (as before)}}\;+\;\underbrace{\ln P(\theta)}_{\text{added log-prior}}\Big]. $$

The E-step is untouched; only the M-step's target gains the $\ln P(\theta)$ penalty (for a coin, this smooths the fractional heads-over-total toward the prior's center, exactly as a prior tempers the plain MLE on thin data). With this single change the same alternation now never decreases the *posterior*, and converges to a stationary point of the penalized objective — the **MAP** estimate. This is the **MAP–EM** variant, and it reframes what EM is: not a separate estimator, but an *algorithm* whose fixed points are the stationary points of whatever objective the M-step optimizes — the (un-penalized) likelihood for the MLE, or the penalized likelihood for the MAP.
