# 일급 함수

## 요약

언어에서 어떤 것이 *일급 시민*(first-class citizen)이라는 것은, 기본 값으로 할 수 있는 모든 일을 그것으로도 할 수 있도록 언어가 허용한다는 뜻이다: 이름에 바인딩하고, 루틴에 전달하고, 결과로 반환하고, 자료 구조에 저장할 수 있다. **일급 함수(first-class function)**는 정확히 이 지위를 누리는 함수다 — 호출만 할 수 있는 고정된, 이름 붙은 존재가 아니라, 숫자나 문자열과 동등한 위치에 있는 그저 또 하나의 값이다. 이 하나의 성질이 *고차 함수*(higher-order function, 다른 함수를 받거나 반환하는 함수)를 가능하게 하며, 콜백(callback), 매개변수화된 동작, 그리고 — 이름이 해석되는 규칙과 결합하여 — 클로저(closure)를 뒷받침하는 원동력이다. 그 결실은 *동작 자체*가 프로그램이 실행 중에 주고받고 만들어낼 수 있는 대상이 된다는 것이다 — 데이터만이 아니라.

## 상세 설명

**핵심 대상.** 많은 오래된 언어에서 함수는 이급(second-class) 존재다: 정의하고 호출할 수는 있지만, 변수에 담거나 다른 함수에 넘길 수는 없다. 함수를 *일급*으로 만든다는 것은 그 제약을 제거하는 것이다 — 함수 값을 다른 어떤 값이 쓰일 수 있는 곳이라면 어디서든 쓸 수 있다. 구체적으로, 네 가지 능력이 합쳐져 일급성을 정의한다: 함수에 **이름을 붙일** 수 있고(변수에 할당), 인자로 **전달할** 수 있고, 다른 함수에서 **반환할** 수 있으며, 식 한가운데에서 익명으로 새 함수를 **생성할** 수 있다. 네 가지를 모두 갖춘 언어는 `1을 더하는 함수`를 `숫자 41`과 종류가 다르지 않은 값으로 취급한다.

**왜 중요한가.** 동작이 값이 되는 순간, 그것을 *추상화의 대상*으로 삼을 수 있다. 정렬 루틴은 원소를 비교하는 방법을 하드코딩할 필요가 없다; 비교 *함수*를 인자로 받아 어떤 순서 기준에 대해서도 동작한다. 이벤트 시스템은 나중에 실행할 함수(콜백)를 저장해 둔다. 어떤 루틴은 요청에 따라 특화된 함수를 *제조*해서 반환할 수 있다. 이 모든 것이 "고차" 프로그래밍이며, 함수가 일급이기 때문에만 존재한다. 이는 또한 클로저에 필요한 것의 절반이기도 하다: 데이터를 여전히 기억하는, 갓 만들어진 함수를 반환하려면, 먼저 함수가 만들고 반환하는 것이 *허용되는* 대상이어야 하고 — 이것이 일급성이다 — 그다음 주변 이름들에 대한 접근을 유지해야 하는데, 그것은 스코프 규칙의 몫이다.

**구체적인 작동 예시.** 두 가지 능력을 함께 보인다. 첫째, 함수를 *전달하기*:

```
function applyTwice(f, x)   -- f is a function value, an ordinary parameter
  return f(f(x))
end

function inc(n) return n + 1 end
applyTwice(inc, 5)          -- inc(inc(5)) = inc(6) = 7
```

여기서 `inc`는 데이터로서 `applyTwice`에 건네지고 그 안에서 호출된다. 둘째, 함수를 *만들어 반환하기*:

```
function adder(n)
  return function(x) return x + n end   -- construct a new function, return it
end

add5 = adder(5)   -- add5 is now a function value
add5(3)           -- 8
add10 = adder(10)
add10(3)          -- 13
```

`adder`는 숫자를 계산하지 않는다 — *함수를 만들어* 반환하며, 반환된 함수는 `add5`에 저장되었다가 나중에 호출된다. 함수가 인자(`applyTwice`)도 될 수 있고 제조된 반환값(`adder`)도 될 수 있다는 것이 퇴화하지 않은(non-degenerate) 시연이다: 일급성이 제공하는 네 가지 능력 — 이름 붙이기, 전달하기, 반환하기, 생성하기 — 을 모두 행사하기 때문이다.
