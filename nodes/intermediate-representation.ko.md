# 중간 표현 (Intermediate Representation)

## 요약

**중간 표현(intermediate representation, IR)**은 프로그램이나 모델을 도구에 독립적인
공통 형태로 나타낸 것이다. 생산자는 자신의 내부 형식을 IR로 변환하고, 여러 소비자는
같은 표현을 검증하거나 변환하거나 실행할 수 있다.

## 상세 설명

두 도구가 계산을 완전히 같은 내부 형식으로 저장하는 경우는 드물다. 모든 생산자와
소비자 쌍을 직접 지원하면 쌍마다 별도 변환기가 필요하다. IR은 중간에 안정적인 계약을
둔다. 각 생산자는 합의된 형식 하나를 내보내고 각 소비자는 그 형식 하나를 읽는다.
생산자 3개와 소비자 2개가 있을 때 쌍별 변환은 `3 × 2 = 6`개 경로가 필요하지만,
공통 IR은 `3 + 2 = 5`개 어댑터가 필요하며 새 도구마다 하나만 더하면 된다.

많은 IR은 구조를 [[graph]]로 표현한다. 정점은 연산이나 대상을 기록하고, 간선은 관계나
값의 흐름을 기록하며, 메타데이터는 이름만으로 표현할 수 없는 세부 사항을 고정한다.
IR 자체가 반드시 실행 가능할 필요는 없다. 목적은 경계를 넘어 의미를 보존하는 것이다.
소비자는 관찰 가능한 계산이 같게 유지되는 한 IR을 직접 해석하거나 최적화하거나 다시
변환할 수 있다.

**구체적인 예.** 생산자 `P`는 “곱한 뒤 더하기”를 자체 객체 트리에 저장하고, 소비자
`C1`과 `C2`는 서로 다른 내부 배치를 사용한다고 하자. `P`는 공통 그래프
`input → multiply → temporary → add → output`을 내보낸다. 두 소비자는 이 하나의
그래프에서 각자 선호하는 구조를 다시 만든다. 이식성은 모든 도구에 같은 구현을 강요해서가
아니라 중간 표현에 합의해서 생긴다.
