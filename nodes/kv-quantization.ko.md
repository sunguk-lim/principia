# KV 캐시 양자화

## 요약

KV 캐시 양자화(KV-cache quantization)는 요청별 키와 값을 더 적은 비트로 저장한다. [[kv-cache]]에 [[quantization]]을 적용하는 것으로, 모델 가중치 정밀도와는 별개다. 메모리 트래픽을 줄이고 수용량을 늘릴 수 있지만, 데이터 비트 수의 비율이 전체 메모리, 정확도 또는 디코딩 속도를 보장하지는 않는다.

## 상세 설명

일반적인 디코더는 과거 토큰의 키와 값을 보존해 재계산을 피한다. 레이어 수, KV 헤드 수와 헤드 폭이 고정되어 있으면 저장할 값은 보존 토큰 수와 동시 시퀀스 수에 따라 증가한다. 가중치만 양자화하면 학습된 매개변수의 저장 형식이 바뀔 뿐, 계산 결과인 캐시 활성값의 정밀도가 자동으로 바뀌지는 않는다. 캐시가 비용을 지배하는지는 작업 부하와 구조에 달려 있으며 모든 길이와 배치에서 성립하지 않는다.

대칭 정수 양자화에서 x는 캐시 스칼라, s는 양의 공유 스케일, q는 가장 가까운 표현 가능 정수 코드다. 클리핑이 없다면 q=round(x/s), 복원값은 x_hat=q×s이며 오차는 최대 s/2다. 4비트 대칭 코드는 -7부터 7까지를 사용할 수 있다. 비대칭 방식에는 영점이 추가된다. FP8이나 코드북 방식은 복원 격자가 다르므로 변환 규칙을 확인하지 않고 균일 격자의 오차 한계를 적용하면 안 된다.

**세분도와 스트리밍.** 텐서별 스케일은 저렴하지만 많은 값이 하나의 범위를 공유한다. 키의 채널별 스케일은 여러 토큰의 같은 좌표를 묶고, 값의 토큰별 스케일은 한 토큰 안의 좌표를 묶는다. KIVI는 조사한 모델의 키 이상값과 값 오차 특성에서 이 비대칭 방식을 도출한다. 블록을 양자화할 때까지 최근 고정밀 잔여 캐시를 유지한다. 이는 검증된 설계 선택이지 모든 모델의 이상값 구조가 같다는 법칙이 아니다. 채널별 블록을 만들려면 필요한 토큰이 먼저 도착해야 한다.

### 계산 예시

두 토큰의 키 행이 각각 [0.5,12], [-0.8,9]이며 채널이 두 개라고 하자. 하나의 4비트 대칭 스케일은 12/7≈1.714이고, 첫 채널의 두 값은 모두 0으로 반올림된다. 채널마다 스케일을 두면 첫 채널은 0.8/7≈0.1143을 사용한다. 코드 [4,-7]은 [0.4571,-0.8]로 복원된다. 두 번째 채널은 12/7≈1.714를 사용하며 코드 [7,5]는 [12,8.571]로 복원된다. 작은 채널의 값이 살아남지만 정확한 복원은 아니며 스케일 두 개가 하나보다 더 많은 공간을 차지한다. 각 스칼라에 독립 스케일을 주는 대신 실제 여러 토큰을 묶은 예시다.

값이 1,000개인 예시 캐시는 16비트에서 데이터만 2,000바이트다. 4비트 코드는 500바이트이며, 4바이트 스케일이 20개면 80바이트가 추가되어 580바이트가 된다. 잔여 버퍼, 패딩과 할당기 비용은 아직 제외한 수치다. 데이터만 보면 4배 감소하지만 이 항목들을 합치면 약 3.45배다. 변환 중 임시 버퍼는 최대 사용량을 더 높일 수 있다.

**다른 오차 제어 방식.** 비균일 방식은 보정 데이터를 이용해 간격이 다른 복원값을 선택한다. KVQuant는 민감도 기반 복원값, 회전 전 키 양자화와 벡터별 밀집·희소 이상값 처리를 연구한다. 희소 값에는 좌표와 명확한 대체 또는 보정 규칙이 필요하다. 무료로 유지되는 고정밀 채널이 아니다. 각 기법을 개별적으로 그리고 조합하여 평가해야 한다.

**수용량과 지연은 다르다.** 캐시 경로가 대역폭에 제한될 수 있지만 가중치 읽기, 커널 실행, 어텐션 연산, 코드 해제, 변환과 스케줄링도 중요하다. 호환되는 융합 커널은 변환 비용을 숨길 수 있지만 호환되지 않는 배치는 트래픽 감소의 이점을 없앨 수 있다. 모델, 프롬프트, 출력 길이, 동시성과 목표 품질을 고정하여 비교하라. 할당·예약 메모리의 최대값, 메타데이터를 포함한 캐시 바이트, 프리필과 토큰 지연, 처리량과 긴 문맥 작업 품질을 측정하라. 드문 오류, 포화, 블록 경계와 분포가 바뀐 입력을 포함해야 한다. 거의 무손실인 정확도나 비트 수에 비례하는 속도 향상은 일반적 보장이 아니다.
