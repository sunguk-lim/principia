# 렉시컬 스코핑

## 요약

이름의 *스코프*(scope)란 그 이름이 유효하며 특정 바인딩을 가리키는 프로그램의 영역이다. **렉시컬 스코핑(lexical scoping)**(정적 스코핑이라고도 한다)은 그 의미를 프로그램의 *씌어진 구조*로 고정한다: 이름의 사용은 소스 텍스트에서 가장 가까운 둘러싸는 블록 또는 함수 안의 선언을 가리키며, 거기서 찾지 못하면 탐색은 둘러싸는 블록들을 거쳐 전역 수준까지 바깥으로 진행된다. 답이 오직 *이름이 코드의 어디에 나타나는가*에만 의존하므로, 프로그램을 읽는 것만으로 모든 이름이 무엇을 의미하는지 판정할 수 있다 — 실행해 볼 필요도, 누가 무엇을 호출했는지 알 필요도 없다. 이 예측 가능성이 렉시컬 스코핑이 현대 언어에서 거의 보편적인 이유이며, 클로저(closure)가 함수를 둘러싼 변수들을 포획할 때 의존하는 규칙이 정확히 이것이다.

## 상세 설명

**핵심 대상.** 프로그램은 이름들로 가득하다 — 변수, 매개변수, 함수 — 그리고 같은 이름이 둘 이상의 장소에서 선언될 수 있다. *스코핑 규칙*이란 이름의 각 *사용*에 대해 그것이 어느 *선언*을 가리키는지를 결정하는 언어의 방법이다. 렉시컬 스코핑은 **소스의 정적 중첩**으로 답한다: 블록과 함수는 텍스트상 서로의 안에 중첩되고, 이름은 그것을 선언하는 가장 안쪽의 둘러싸는 블록으로 해석되며, 사용 지점에서 바깥쪽으로 — 안쪽 블록, 그다음 그것을 둘러싼 블록, 그렇게 전역 스코프까지 — 탐색한다. *렉시컬*이라는 단어가 뜻하는 바가 정확히 이것이다: 해석이 텍스트(lexis)의 속성이며, 무엇이든 실행되기 전에 확정된다.

**왜 작동하는가 — 그리고 의미를 부여하는 대조.** 대안은 *동적 스코핑*(dynamic scoping)으로, 이름이 *런타임 호출 사슬*에서 가장 최근의 바인딩으로 해석된다 — 즉 *누가 당신을 호출했는가*에 의존하며, 이는 호출마다 달라질 수 있다. 렉시컬 스코핑은 대신, 함수의 자유 이름(free name, 함수가 사용하지만 스스로 선언하지 않는 이름)이 나중에 어디서 호출되든 상관없이 *그 함수가 씌어진 자리에서* 의미했던 것을 의미한다고 보장한다. 그 보장이 *국소적 추론*(local reasoning)을 가능하게 한다: 가능한 모든 호출자를 추적하지 않고도, 함수와 그 주변 텍스트를 읽는 것만으로 함수를 이해할 수 있다. 이는 또한 클로저가 딛고 서는 토대이기도 하다 — "둘러싼 변수들을 포획한다"가 잘 정의되는 것은, 함수의 이름들이 정확히 어떤 둘러싼 변수들을 가리키는지를 렉시컬 스코핑이 말해 주기 때문이다.

**구체적인 작동 예시.** 일부러 이름을 재사용한 중첩 정의를 보자:

```
x = 1                     -- a global x

function outer()
  x = 2                   -- a new, local x, shadowing the global inside outer
  function inner()
    return x              -- which x?
  end
  return inner
end

f = outer()
result = f()
```

`inner`의 `x`를 씌어진 중첩에 따라 해석하자: `inner`는 자신의 `x`를 선언하지 않으므로 한 단계 바깥을 본다 — `outer`가 지역 `x = 2`를 선언한다. 발견. 따라서 `inner`는 `2`를 반환하며, *`f()`가 최상위 — 보이는 `x`가 전역 `1`인 곳 — 에서 호출되었음에도* `2`를 반환한다. 호출의 런타임 위치는 무관하다; 오직 `inner`의 텍스트상 거처만이 중요하다. 재사용된 이름(`outer` 안의 지역 `x`가 전역 `x`를 *가리는(shadowing)* 것)이 퇴화하지 않은(non-degenerate) 재료다: 바깥쪽으로의 탐색이 안쪽 선언에서 멈추도록 강제하고, 렉시컬 대 동적의 구분을 눈에 보이게 만든다 — 동적 스코핑이었다면, 최상위에서 호출된 `f()`는 대신 전역 `x = 1`을 보고 `1`을 반환했을 것이다.
