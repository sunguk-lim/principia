# 로그 레코드

## 요약

**로그 레코드(log record)**는 한 [[event]]를 특정 시점에 기록한다. 구조화된 형태는
타임스탬프, 심각도, 본문, 상관관계 ID 같은 정해진 필드와 출처·발생을 설명하는 임의의
[[key-value]] 속성을 결합한다.

## 상세 설명

텍스트와 구조의 차이는 계약이다. `ERROR checkout failed user=42`라는 줄은 사람이 읽기
쉽지만 소비자마다 파싱 방법을 추측해야 한다. 구조화 레코드는
`{timestamp: 10:00:00.180, severity: ERROR, event: checkout.failed,
user_id: 42}`라고 명시할 수 있다. 안정된 필드 이름과 타입 덕분에 하류 도구가 심각도로
필터링하고, 이벤트 이름으로 묶고, 숫자를 텍스트 파싱 없이 보존할 수 있다.

요청 하나 안에서 결제가 실패했다고 하자. [[event]]는 “결제가 거절되었다”다. 로그
레코드는 발생 시각, 출처, 심각도, `order_id=817` 같은 필드를 더한다. 트레이스 ID와
스팬 ID도 있으면 같은 레코드를 그것을 발생시킨 작업 옆에 표시할 수 있다. 로그는 계속
한 시점의 발생이며, 상관관계 필드가 있다고 지속 시간으로 바뀌지는 않는다.

비구조 로그도 사람과 기존 애플리케이션에 유용하므로 OpenTelemetry는 모든 프로그램에
새 로깅 API를 강요하기보다 수집하고 정규화할 수 있다. 규모가 커질수록 구조가 중요해진다.
기계가 민감한 속성을 안정적으로 가리고, 선택한 레코드를 라우팅하며, 다른 텔레메트리와
로그를 결합할 수 있기 때문이다.
