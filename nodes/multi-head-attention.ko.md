# 멀티헤드 어텐션 (Multi-Head Attention)

## 요약

하나의 [[transformer-attention]]은 토큰들에 대해 **단일한** 가중치 부여만
만들어낸다 — 그래서 한 번에 오직 한 종류의 관계만 강조할 수 있다.
**멀티헤드 어텐션(multi-head attention)**은 $h$개의 어텐션을 각자 학습된
표현의 부분 공간(slice) 위에서 *병렬로* 실행한 뒤, 결과를 다시 붙여 합친다.
각 헤드가 $h$배 좁은 공간에서 작동하기 때문에, $h$개의 헤드를 합쳐도 완전한
크기의 어텐션 하나와 비용이 거의 같다 — 그 결과 모델은 사실상 **공짜로**
여러 관계에 동시에 주의를 기울인다.

## 상세 설명

**1 · 기호** — 🟦 스칼라 · 🟩 벡터 · 🟧 행렬

| 기호 | 종류 | 형태 | 의미 |
|--------|------|-------|---------|
| $X$ | 🟧 행렬 | $n\times d$ | 입력 — 토큰당 $d$차원 행 하나 |
| $h$ | 🟦 스칼라 | — | 헤드 개수 |
| $d_\text{head}$ | 🟦 스칼라 | — | 헤드당 폭, $= d/h$ |
| $W_q^i, W_k^i, W_v^i$ | 🟧 행렬 | $d\times d_\text{head}$ | 헤드 $i$의 학습된 투영 |
| $\text{head}_i$ | 🟧 행렬 | $n\times d_\text{head}$ | 하나의 [[transformer-attention]]의 출력 |
| $W_o$ | 🟧 행렬 | $d\times d$ | 헤드들을 섞는 출력 투영 |
| $\text{MHA}(X)$ | 🟧 행렬 | $n\times d$ | 최종 출력 |

**2 · 수식**

$$\text{MHA}(X) = \mathrm{Concat}(\text{head}_1,\dots,\text{head}_h)\,W_o,
\qquad \text{head}_i = \mathrm{Attention}\!\left(X W_q^i,\; X W_k^i,\; X W_v^i\right)$$

여기서 $\mathrm{Attention}$은 정확히 [[transformer-attention]]이며, 헤드 $i$
자신의 부분 공간 안에서 실행된다.

**정의.** 각 헤드 $i$는 먼저 [[matrix-multiplication]]을 통해 입력을 자신의
$d_\text{head}$차원 부분 공간으로 **투영**한다: $X W_q^i$, $X W_k^i$,
$X W_v^i$. 그런 다음 그곳에서 일반적인 [[transformer-attention]]을 실행하여
$\text{head}_i$ (형태 $n\times d_\text{head}$)를 얻고, $h$개의 헤드 출력을
다시 폭 $d$로 **연결(concatenate)**한 뒤 하나의 $W_o$로 재결합한다. 정의하는
대상은 헤드 내부의 어텐션(이것은 전제 조건이다)이 아니라, *서로 다른 투영
위에 놓인 병렬 헤드들의 집합* 더하기 연결-및-혼합 과정이다.

**하나의 큰 헤드 대신 나누는 이유.** 단일 어텐션은 쿼리마다 **하나의**
[[transformer-attention]] 가중치만 내놓으므로, 그 출력은 하나의 가중
평균이다 — 한 번에 오직 한 가지 관계 패턴만 표현할 수 있다 (예: "이전
토큰을 보라"). 서로 다른 투영을 가진 $h$개의 헤드를 모델에 주면, 같은
토큰들에 대해 $h$개의 **독립적인** 가중치 부여가 만들어지고, 연결 연산
덕분에 결과는 그 모두를 동시에 담을 수 있다 (한 헤드는 주어를 추적하고,
다른 헤드는 인접 단어를, 또 다른 헤드는 장거리 참조를 추적할 수 있다). 이를
저렴하게 만드는 항등식은 다음과 같다: $d_\text{head} = d/h$일 때, $h$개의
투영 행렬 $W^i$는 하나의 완전한 폭의 어텐션이 사용할 것과 *같은* $d\times d$
행렬로 쌓인다 — 그래서 $h$개의 좁은 헤드는 하나의 넓은 헤드와 **같은**
파라미터 수와 [[matrix-multiplication]] 비용을 가진다. 여러 관계를 동시에
혼합하는 것은 사실상 공짜로 얻어진다.

**예시.** $d = 4$, $h = 2$ (따라서 $d_\text{head} = 2$), 토큰 두 개, 토큰
1을 쿼리로 놓는다. 계산 과정을 눈에 보이도록 각 헤드의 투영이 단순히 두
좌표를 *선택*한다고 하자: 헤드 1은 차원 1–2를 읽고, 헤드 2는 차원 3–4를
읽는다.

- **헤드 1** (차원 1–2): 쿼리 $q = [1,0]$; 키 $k_1 = [1,0],\, k_2 = [0,1]$;
  값 $v_1 = [2,0],\, v_2 = [0,2]$. 점수는 $q\!\cdot\!k_1 = 1,\
  q\!\cdot\!k_2 = 0$; $\sqrt{d_\text{head}} = \sqrt2$로 스케일링하면
  $[0.71,\,0]$; [[softmax]] 적용 시 $\to [0.67,\,0.33]$. 따라서
  $\text{head}_1 = 0.67\,[2,0] + 0.33\,[0,2] = [1.34,\,0.66]$.
- **헤드 2** (차원 3–4): 쿼리 $q = [0,1]$; 같은 키; 값 $v_1 = [3,0],\,
  v_2 = [0,3]$. 점수 $[0,\,1]$, 스케일링하면 $[0,\,0.71]$; [[softmax]]
  적용 시 $\to [0.33,\,0.67]$. 따라서
  $\text{head}_2 = 0.33\,[3,0] + 0.67\,[0,3] = [0.99,\,2.01]$.
- **연결** $\to [1.34,\,0.66,\;0.99,\,2.01]$, 다시 폭 $d = 4$로; $W_o = I$일
  때 이것이 $\text{MHA}(X)$다.

효과는 숫자 안에 그대로 드러난다: **같은** 두 토큰으로부터, 헤드 1은 토큰
1에 기울어졌고 (가중치 $0.67$) 헤드 2는 토큰 2에 기울어졌다 (가중치
$0.67$) — 헤드들이 서로 다른 부분 공간을 바라보기 때문에 정확히 *다른* 두
관계가 동시에 포착된 것이다. 단일 헤드였다면 둘 중 하나만 보고할 수 있었을
것이다.

**작동 위치.** $h$개의 헤드는 서로 독립적이므로, 하드웨어는 이들을 하나의
일괄 처리된 행렬 곱셈 집합으로 계산한다 — 이들이 대체하는 단일 넓은
어텐션보다 느리지 않다. 이후에 중요해지는 한 가지 결과: 각 헤드는 자신만의
키와 값을 유지하며, 생성 과정에서 이것들이 헤드마다 누적된다 — 이것이
정확히 그룹 쿼리 어텐션(grouped-query attention)이 줄이려고 만들어진
헤드당 메모리 비용이다.
