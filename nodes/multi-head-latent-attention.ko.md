# 멀티헤드 잠재 어텐션 (Multi-Head Latent Attention)

## 요약

[[kv-cache]]는 생성 과정의 메모리 병목이며, [[multi-head-attention]]에서는
과거의 모든 토큰에 대해 **모든 헤드**의 키와 값을 저장한다. **멀티헤드
잠재 어텐션(multi-head latent attention, MLA)**은 [[low-rank-factorization]]을
이용해 이 캐시를 줄인다: 모든 헤드의 `K`와 `V`를 캐싱하는 대신, 토큰마다
**하나의 작은 잠재 벡터(latent vector)**만 캐싱하고 필요할 때마다 각
헤드의 `K`/`V`를 그로부터 **재구성**한다. 결정적으로, 각 헤드는 자신만의
업-투영(up-projection)으로부터 재구성하므로 헤드들은 서로 구별된 채로
남는다 — MLA는 헤드 하나를 공유하는 것만큼 작은 캐시를 얻으면서도 완전한
멀티헤드 어텐션의 품질을 유지한다.

## 상세 설명

**1 · 기호** — 🟦 스칼라 · 🟩 벡터 · 🟧 행렬

| 기호 | 종류 | 형태 | 의미 |
|--------|------|-------|---------|
| $x_t$ | 🟩 벡터 | $d$ | 토큰 $t$의 입력 ($d$ = 모델 폭) |
| $h$ | 🟦 스칼라 | — | 헤드 개수 ([[multi-head-attention]]에서) |
| $d_\text{head}$ | 🟦 스칼라 | — | 헤드당 폭 |
| $c_t$ | 🟩 벡터 | $d_c$ | 토큰 $t$의 **잠재 벡터**; $d_c \ll h\,d_\text{head}$ |
| $W^{DKV}$ | 🟧 행렬 | $d_c \times d$ | 다운-투영 (압축) |
| $W^{UK,i}, W^{UV,i}$ | 🟧 행렬 | $d_\text{head}\times d_c$ | 헤드 $i$의 업-투영 (재구성) |
| $q_t^i, k_t^i, v_t^i$ | 🟩 벡터 | $d_\text{head}$ | 토큰 $t$에 대한 헤드 $i$의 쿼리 / 키 / 값 |

**2 · 수식**

$$c_t = W^{DKV} x_t \quad\text{(압축 — 캐싱되는 것은 오직 이 잠재 벡터뿐)}$$

$$k_t^i = W^{UK,i}\, c_t, \qquad v_t^i = W^{UV,i}\, c_t \quad\text{(필요할 때 헤드 } i \text{를 재구성)}$$

**정의.** MLA는 [[multi-head-attention]]의 $h$개 병렬 헤드는 그대로 두지만,
[[kv-cache]]가 보관하는 내용을 바꾼다. 일반적인 멀티헤드 디코딩은 모든
헤드의 키와 값을 캐싱한다 — 토큰당 $2\,h\,d_\text{head}$개의 숫자다. 대신
MLA는 토큰을 크기 $d_c \ll h\,d_\text{head}$인 저랭크 잠재 벡터 $c_t$로
**다운-투영**하고 (키/값 내용의 [[low-rank-factorization]]), **오직
$c_t$만 캐싱**한다. 각 헤드의 `K`와 `V`는 그 공유된 잠재 벡터에 자신만의
**업-투영** $W^{UK,i}, W^{UV,i}$를 적용해 복원된다.

**작동 원리 — 그리고 지나치게 저렴해 보이는 단계.** 두 가지 질문이 있다:
작은 캐시가 정보를 잃지는 않는가, 그리고 매 스텝마다 $K$/$V$를 재구성하는
것은 추가 연산 비용이 들지 않는가?

- *품질.* 각 헤드가 **서로 다른** 업-투영을 갖기 때문에, 두 헤드는 *같은*
  잠재 벡터로부터 **서로 다른** 키를 복원한다 — [[multi-head-attention]]에
  표현력을 부여하는 헤드 다양성이 보존된다. (대조적으로 그룹 쿼리
  어텐션은 헤드들이 `K`/`V`를 *공유*하게 만들어 캐시를 줄이며, 그 다양성의
  일부를 포기한다.)
- *연산 — 흡수 항등식(absorption identity).* 실제로 $k_j^i$를 다시 만들
  필요는 전혀 없다. 점수는 내적(dot product)이며, 투영된 벡터에 대한
  내적은 재결합될 수 있다:
  $$q_t^i \cdot k_j^i = q_t^i \cdot \big(W^{UK,i} c_j\big) = \big(W^{UK,i\top} q_t^i\big)\cdot c_j .$$
  즉 $W^{UK,i}$는 한 번 **쿼리 안으로 흡수되며**, 점수는 **캐싱된 잠재
  벡터** $c_j$에 대해 **직접** 계산된다 — 헤드별 키 재구성이 전혀 필요
  없다. 같은 트릭이 값 쪽에서도 $W^{UV,i}$를 출력 투영 안으로 흡수한다.
  작은 캐시는 어텐션 계산 시점에 사실상 아무 비용도 들지 않는다.

(솔직히 말할 부분: 키의 위치 의존적인 작은 부분은 별도로, 압축하지 않은
채 보관된다. 위치 정보가 섞이면 그 흡수 관계가 더 이상 성립하지 않기
때문이다; 잠재 벡터는 대부분을 차지하는 내용 부분만을 압축한다.)

**예시.** $d = 4$, $h = 2$, $d_\text{head} = 2$, 잠재 벡터 크기 $d_c = 2$를
가정하자. 멀티헤드 어텐션이라면 캐시는 토큰당 $2\,h\,d_\text{head} = 8$개의
숫자를 (두 헤드의 `K`와 `V` 모두) 보관할 것이다; MLA는 $d_c = 2$개만
보관한다.

- 토큰 $x_t = [2,0,1,0]$. $W^{DKV} = \begin{bmatrix}1&0&0&0\\0&0&1&0\end{bmatrix}$
  (차원 1과 3을 읽는다)로 다운-투영하면: $c_t = [2,\,1]$. **이 두 숫자만
  캐싱한다.**
- 각 헤드의 업-투영으로 키를 재구성한다: 헤드 1은
  $W^{UK,1} = \begin{bmatrix}1&0\\0&1\end{bmatrix} \Rightarrow k_t^1 = [2,1]$을
  사용하고; 헤드 2는
  $W^{UK,2} = \begin{bmatrix}0&1\\1&0\end{bmatrix} \Rightarrow k_t^2 = [1,2]$를
  사용한다. 같은 잠재 벡터에서 **서로 다른 두 키**가 나온다 — 압축을
  거쳐도 헤드 다양성이 살아남는다.
- 쿼리 $q^1 = q^2 = [1,0]$으로 흡수 항등식을 확인해보자:
  - 헤드 1, 직접 계산: $q^1\!\cdot k^1 = [1,0]\!\cdot[2,1] = 2$; 흡수
    계산: $(W^{UK,1\top}q^1)\!\cdot c_t = [1,0]\!\cdot[2,1] = 2$. ✓
  - 헤드 2, 직접 계산: $q^2\!\cdot k^2 = [1,0]\!\cdot[1,2] = 1$; 흡수
    계산: $(W^{UK,2\top}q^2)\!\cdot c_t = [0,1]\!\cdot[2,1] = 1$. ✓
  키를 재구성하든 캐싱된 잠재 벡터에 대해 직접 점수를 계산하든 두
  헤드의 점수는 동일하게 나온다 — 그래서 MLA는 어텐션 결과의 변화 없이
  8개가 아니라 2개의 숫자만 저장한다.

**작동 위치.** [[kv-cache]]에서 보았듯, 캐시 메모리는 $\propto 2 \times
n_\text{tokens} \times n_\text{layers} \times (\text{토큰당 KV 크기})$에
비례하며, 긴 컨텍스트나 큰 배치에서는 이것이 추론 비용을 지배한다. MLA는
토큰당 항목을 $2\,h\,d_\text{head}$에서 $d_c$로 줄인다 — 단일 헤드를
공유하는 수준의 캐시이면서도, 헤드별 업-투영 덕분에 완전한
[[multi-head-attention]]의 품질을 유지한다.
