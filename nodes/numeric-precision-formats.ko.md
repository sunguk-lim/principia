# 수치 정밀도 형식 (Numeric Precision Formats)

## 요약

수치 정밀도 형식은 비트 패턴이 어떤 값을 나타내는지 정한다. 부동소수점 형식은 비트를 부호, 지수, 소수부에 나누어 쓰고, 정수 형식은 별도의 [[quantization]] 스케일로 해석할 수 있는 정수 코드를 표현한다. 비트 수는 명목상 데이터 저장량을 결정하지만, 보편적인 속도나 정확도 보장은 아니다.

## 상세 설명

정규 이진 부동소수점 수의 값은 $(-1)^s(1+f)2^e$로 쓸 수 있다. 여기서 $s$는 부호 비트, $f$는 저장된 소수부의 기여분, $e$는 바이어스를 제거해 해석한 지수다. 정규값에서는 맨 앞의 1을 암묵적으로 사용한다. 영, 비정규값, 무한대, NaN에는 형식별 규칙이 필요하므로 이 식이 모든 비트 패턴을 설명하지는 않는다.

일반적으로 지수 비트가 많을수록 표현 가능한 크기 범위가 넓고, 소수부 비트가 많을수록 같은 크기 부근의 간격이 촘촘하다. FP32는 부호 1비트, 지수 8비트, 소수부 23비트를 쓴다. FP16은 1, 5, 10비트를, BF16은 1, 8, 7비트를 쓴다. 뒤의 두 형식은 모두 16비트지만 BF16은 소수부 해상도를 줄여 지수 범위를 넓힌다. 이는 일부 학습 작업에서 오버플로를 줄이는 대신 반올림 오차를 늘릴 수 있다. 적절한 선택은 연산 특성과 품질 요구에 달려 있다.

INT8과 INT4는 각각 8비트와 4비트 정수 코드를 사용한다. 응용에서는 코드를 예약하거나 실제 범위를 제한할 수 있다. 예를 들어 대칭 양자화는 4비트가 열여섯 패턴을 표현할 수 있어도 -7부터 7까지의 코드를 자주 사용한다. 표현되는 실수는 정수 비트 패턴뿐 아니라 저장된 스케일과 영점에 의존한다. 형식 이름만으로 텐서 그룹, 보정 방식, 누산 정밀도가 정해지지는 않는다.

저비트 부동소수점 형식도 지수, 소수부, 특수값 규칙이 다르다. E4M3와 E5M2는 8비트 안의 서로 다른 배분을 나타낸다. 정확한 유한값 범위와 오버플로 처리는 문서화된 변형에 따라 다르다. 4비트 저장이 추론 경로 전체의 4비트 연산을 뜻하지는 않는다. 압축 해제, 스케일 적용, 누산에는 더 넓은 값이 사용될 수 있다.

## 값 예제: 범위와 해상도

70000을 보자. FP16의 최대 유한값은 65504이므로 이 값을 최근접 반올림으로 변환하면 무한대로 넘친다. BF16은 이 크기를 표현할 수 있다. $2^{16}=65536$ 부근에서 소수부 7비트의 간격은 $2^{16}/2^7=512$다. 인접한 BF16 값은 69632와 70144이고 70000과의 거리는 각각 368과 144다. 따라서 최근접 반올림은 70144를 선택한다. 넓은 범위 덕분에 유한값을 유지했지만 해상도 때문에 144의 오차가 생겼다. 같은 비트 수가 같은 표현값을 뜻하지는 않는다.

## 저장 예제: 데이터 자체와 전체 메모리

가상의 십억 개 가중치는 16비트에서 $10^9\times16/8=2\times10^9$바이트, 4비트에서 $10^9\times4/8=0.5\times10^9$바이트의 순수 데이터 공간을 요구한다. 이상적인 가중치 데이터 감소율은 네 배다. 이는 십진 단위로 2.0 GB와 0.5 GB이며, $2^{30}$으로 나누면 약 1.863 GiB와 0.466 GiB다. 실제 상주 메모리에는 스케일 메타데이터, 변환하지 않은 텐서, 임시 버퍼, 실행 상태를 더해야 한다. 학습은 기울기와 옵티마이저 상태를, 생성은 어텐션 상태를 추가로 유지한다. 이 모든 요소가 가중치 비트 수 비율대로 줄지는 않는다.

## 검증과 한계

지원 커널, 텐서 모양, 메모리 이동, 변환 비용, 작업 부하가 실행 시간을 결정한다. 저장 비트가 줄면 이동량을 줄이거나 더 많은 압축 연산을 처리할 수 있지만 처리량이 비례해 늘어난다는 보장은 없다. 같은 모양과 품질 기준에서 실제 백엔드를 측정하고, 순수 데이터 공간과 최대 할당·예약 메모리를 구분하며, 범위 초과와 작업 수준 오차를 함께 보고한다.

어떤 형식도 보편적으로 1% 미만의 품질 손실을 보장하지 않는다. 배포된 누산·스케일 정책으로 반올림, 오버플로, 언더플로와 대표적인 전체 출력을 시험해야 한다. 하드웨어 지원이라는 표시만으로 모든 연산이 효율적인 저비트 경로를 사용한다고 판단할 수 없다.
