# 관측 가능성 계측

## 요약

**관측 가능성 계측(observability instrumentation)**은 애플리케이션 활동을 관찰해
[[telemetry-signal]]을 내보내는 코드나 런타임 통합이다. 프로그램 내부의 작업과 외부에서
볼 수 있는 증거를 연결해 시스템에 [[observability]]을 주는 다리다.

## 상세 설명

코드 기반 계측은 다리를 명시적으로 만든다. 결제 핸들러가 작업 레코드를 시작하고,
`cart.items=3`을 붙이고, 지속 시간을 기록한 뒤 핸들러가 반환할 때 레코드를 끝낼 수
있다. 개발자가 도메인 고유 지점과 속성을 선택하므로 풍부한 증거를 얻지만 소스 변경이
필요하다.

제로 코드 계측은 에이전트, 런타임, 라이브러리 통합을 통해 같은 종류의 훅을 삽입한다.
비즈니스 코드를 바꾸지 않고 들어오는 요청, 데이터베이스 호출, 메시지 소비자 같은 공통
경계를 감쌀 수 있다. 도입이 빠르고 범위가 넓지만 “쿠폰 거절” 같은 애플리케이션 고유
의미보다 표준 라이브러리 작업을 더 쉽게 본다. 두 방식을 함께 사용할 수 있다.

결정적인 요구 사항은 작업 생명주기와 문맥을 올바르게 보존하는 것이다. 레코드를 시작하고
끝내지 않거나, 잘못된 부모를 기록하거나, 메트릭마다 고유 사용자 ID처럼 끝없이 늘어나는
속성을 내보내면 결과 [[telemetry-signal]]이 오해를 부르거나 비싸진다. 따라서 계측은
단순히 “로깅 켜기”가 아니라 의도적으로 정한 관찰 경계다.
