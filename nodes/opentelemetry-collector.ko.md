# OpenTelemetry Collector

## 요약

**OpenTelemetry Collector**는 [[telemetry-signal]] 데이터를 수신하고, 처리하고, 내보내는
공급자 중립 서비스다. 애플리케이션을 백엔드별 프로토콜과 배치, 재시도, 필터링, 가림
처리 같은 운영 책임에서 분리한다.

## 상세 설명

Collector 파이프라인에는 순서가 있는 세 역할이 있다. **리시버(receiver)**는 예를 들어
HTTP 위의 OTLP로 들어오는 데이터를 받는다. 0개 이상의 **프로세서(processor)**가 순서대로
데이터를 바꾼다. 레코드를 배치하고, 원하지 않는 속성을 버리고, 환경 메타데이터를 더하고,
샘플링할 수 있다. **익스포터(exporter)**는 결과를 목적지로 보낸다. Collector 하나가
구성 요소를 공유하면서 트레이스, 메트릭, 로그 파이프라인을 따로 실행할 수 있다.

서비스 세 개가 초당 [[telemetry-signal]] 항목 100개씩 내보낸다고 하자. Collector가
없으면 각 서비스가 백엔드 자격 증명, 재시도 로직, 공급자 전용 익스포터를 가져야 한다.
Collector를 두면 셋 모두 로컬 OTLP 엔드포인트 하나로 보낸다. 배치 프로세서는 1초 동안
도착한 300개를 더 적은 네트워크 요청으로 묶고, 속성 프로세서는 `customer.email`을
제거하며, 두 익스포터는 정리된 데이터를 운영 백엔드와 보관소로 복사한다. 애플리케이션은
목적지를 알 필요가 없다.

Collector는 애플리케이션 옆의 에이전트, 공유 게이트웨이, 또는 두 계층 모두로 실행할
수 있다. 에이전트는 데이터를 빨리 넘기고 로컬 리소스 정보를 붙일 수 있으며, 게이트웨이는
라우팅과 정책을 중앙화한다. Collector 자체는 저장·시각화 백엔드가 아니다. 모든 익스포터가
버퍼와 재시도 용량보다 오래 실패하면 데이터는 여전히 손실될 수 있다. 정의적인 역할은
제어 가능한 수신 → 처리 → 내보내기 경계다.
