# 파이프라인 병렬화 (Pipeline Parallelism)

## 요약

**파이프라인 병렬화(pipeline parallelism)**는 [[neural-network]]를
**레이어(layer)** 단위로 나눈다 — 각 GPU가 연속된 레이어 블록 (하나의
*스테이지(stage)*)를 담당한다 — 그리고 데이터를 마치 조립 라인처럼
스테이지들을 통과시킨다. 모든 스테이지를 계속 바쁘게 만들기 위해,
배치는 **마이크로배치(micro-batch)**로 잘려 파이프라인을 하나씩 차례로
흘러간다. 스테이지들은 오직 **활성값(activation)** (순전파)과
**기울기(gradient)** (역전파)만 주고받으며, 이는 [[message-passing]]을
통해 **일대일(point-to-point)**로 전달된다 — **집합 통신(collective)**은
전혀 없다. 파이프라인이 채워지고 비워지는 동안 피할 수 없는 유휴
시간이 바로 **버블(bubble)**이다.

## 상세 설명

데이터 병렬화가 모델을 복제하고 텐서 병렬화가 각 가중치를 샤딩하는
것과 달리, 파이프라인 병렬화는 모델을 **깊이 방향으로** 나눈다:

1. **레이어 → 스테이지.** [[neural-network]]의 레이어들을 `P`개의
   연속된 블록으로 잘라, GPU마다 하나씩 배정한다. 순전파 활성값은
   `스테이지 0 → 1 → 2 → 3`으로 흐른다; 역전파는 [[gradient]]를 반대
   방향인 `3 → 2 → 1 → 0`으로 보낸다 (연쇄 법칙).
2. **의존성 문제.** 스테이지 `i+1`은 스테이지 `i`가 자신의 활성값을
   만들어내기 전까지는 시작할 수 없다. 단일 배치를 실행하면 한
   번에 오직 **하나**의 GPU만 바쁘고 — 나머지는 유휴 상태다. 이는
   전체 취지를 무너뜨린다.
3. **마이크로배치가 파이프를 채운다.** 배치를 `M`개의 마이크로배치로
   나눈다. 스테이지 0이 마이크로배치 0을 끝내자마자 그 활성값을
   스테이지 1에 넘기고 (일대일 [[message-passing]] 전송) 즉시
   마이크로배치 1을 시작한다. 이제 모든 스테이지가 동시에 *서로
   다른* 마이크로배치를 처리한다 — 그림에 나오는 대각선 캐스케이드다
   (`G0→G1→G2→G3`을 따라가는 하나의 색깔을 보라).
4. **버블.** 시작 시점 (채워지는 동안)과 끝 시점 (비워지는 동안)에는
   일부 스테이지가 할 일이 없다 — 스케줄에서 비어 있는 삼각형들이다.
   그 유휴 비율은 대략 `(P-1)/(M+P-1)`이므로, **마이크로배치가
   많을수록 → 버블이 비례해서 작아지고** 활용률이 높아진다.
5. **통신은 집합 통신이 아니라 일대일이다.** 스테이지 경계를 넘는
   것은 오직 활성값과 기울기뿐이며, 각각은 *다음* 스테이지로 향하는
   단일 [[message-passing]] 전송이다 — 그룹 전체에 대한 all-reduce는
   결코 없다. 이는 대역폭 요구량을 아주 작게 만들어, 파이프라인
   병렬화가 느린 링크로 연결된 노드들 사이에서도 동작하게 한다.

세 전략을 관통하는 대조점은 통신 패턴이다: **데이터 병렬화**는
스텝마다 한 번씩 *기울기*를 all-reduce하고; **텐서 병렬화**는
레이어마다 한 번씩 *활성값*을 all-reduce하며; **파이프라인
병렬화**는 인접한 스테이지 사이에 *활성값*을 일대일로 보내며, 집합
통신은 전혀 없다. 이것이 GPU 하나에 담기엔 너무 깊은 모델을 애초에
학습 가능하게 만들어주는 것이다 — 버블과, 전송 중인 활성값을
저장해야 하는 비용을 대가로 치른다.
