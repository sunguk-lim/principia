# 양자화

## 요약

양자화(quantization)는 숫자를 촘촘하지 않게 균등한 간격으로 배치된 정수
수준(level) 중 하나로 반올림하고 하나의 스케일 숫자를 기억함으로써 **더
적은 비트**로 저장한다. 보통 넓은 부동소수점 값으로 저장되던 `3.1` 같은
가중치는 작은 정수 코드(예를 들어 `7`)와 공유된 **스케일(scale)**
`s ≈ 0.443`이 되며, 이를 다시 읽어들일 때는 곱셈을 한다: `7 × 0.443 ≈ 3.1`.
수준의 개수가 얼마 되지 않기 때문에 대부분의 값은 두 수준 *사이*에 놓여
반올림되어야 한다 — 그래서 양자화는 작고 유계인 **반올림 오차(rounding
error)**를 감수하는 대신 메모리와 숫자를 옮기는 데 걸리는 시간을 크게
절약한다. 이 방식 전체는 나눗셈, 반올림, 곱셈 — 즉 [[arithmetic]] — 일 뿐이다.

## 상세 설명

**문제.** 신경망은 (가중치와 그것이 만들어내는 활성화라는) 숫자들의 긴
목록이다. 각 숫자는 보통 많은 비트로 저장된다 — 흔히 쓰이는 반정밀도 부동
소수점 "FP16"은 16비트다 — 그래서 수십억 개의 숫자를 가진 모델은 수십억
개의 16비트 슬롯이 필요하다. 메모리는 유한하며, 더 흔하게는 이 숫자들을
메모리에서 산술 연산 장치로 *옮기는* 것이 병목이 된다. 비트 수를 절반으로
줄이면 두 비용 모두 대략 절반이 된다. 그래서 이렇게 묻는다: 각 숫자를 8
비트("INT8")나 심지어 4비트("INT4") — 즉 평범한 부호 있는 정수 — 로
표현하면서도 원래 값에 대한 좋은 근사를 여전히 복원할 수 있을까?

**핵심 대상: 스케일.** `b`비트 부호 있는 정수는 고정된 정수 *코드*의
집합만 담을 수 있다. `b`비트로는 가장 큰 크기의 코드가
`q_max = 2^(b−1) − 1`이다(`−1`은 한 비트가 부호를 결정하고, 또 하나의 코드는
0 또는 음수 쪽에 쓰이기 때문이다). `b = 4`일 때: `q_max = 2^3 − 1 = 7`이므로
코드는 `−7 … +7`까지다. 이 코드들은 균등한 간격의 정수이지만, 실제
가중치는 정수가 아니고 다른 범위에 걸쳐 있다. 양자화는 **하나의 공유된
실수, 스케일 `s`**로 둘을 연결한다: 코드 `q`는 실제 값 `q × s`를
*나타낸다*. `s`를 고르는 것이 이 게임의 전부다 — 정수 한 단계가 실제
세계에서 얼마만큼의 값을 갖는지를 결정하기 때문이다.

**왜 스케일은 `max(|x|) / q_max`인가.** 그룹 안에서 *가장 큰 크기*의 값이
코드 범위를 넘치지 않고 표현될 수 있기를 원한다. 가장 큰 크기가
`M = max(|x|)`이고 가장 큰 코드가 `q_max`라면, `s = M / q_max`로 설정하면
그 극단값이 정확히 극단 코드로 매핑되고(`M / s = q_max`), 그보다 작은 모든
값은 `[−q_max, q_max]` 범위 *안*에 들어온다. `s`를 그보다 더 작게 고르면 가장
큰 값들이 범위를 넘쳐서(클리핑) 잘리고, 더 크게 고르면 절대 쓰이지 않는
코드를 낭비하여 모든 값을 불필요하게 거칠게 만든다. 그래서
`s = max(|x|) / q_max`는 클리핑으로 아무것도 잃지 않는 가장 빡빡한 스케일이다.
이것이 **대칭(symmetric)** 방식이다: 실수 범위 `[−M, +M]`은 0을 중심으로
하고, 코드 `0`은 항상 실수 `0`을 의미한다.

**양자화와 역양자화.** `s`를 고정하면, 두 세계를 오가는 두 연산이 생긴다.
실수 값 `x`를 코드로 **양자화**하려면: 스케일로 나누고 가장 가까운 정수로
반올림한다.

  `q = round(x / s)`.

이를 실수 값으로 다시 읽어들이는 **역양자화(dequantize)**는:

  `x̂ = q × s`.

반올림이 유일하게 정보를 잃는 단계다 — 그리고 바로 이 지점이 양자화를
양자화답게 만드는 곳이므로 자세히 들여다보자. `q`가 `x / s`에 가장 가까운
정수이므로, 남는 오차 `x/s − q`는 크기가 최대 `½`이다. 이를 다시 `s`로
곱하면, 복원된 값 `x̂`는 `x`와 최대 `s/2`만큼 차이난다. 이것이 **양자화
오차(quantization error)**이며, 이는 *유계*다: `|x̂ − x| ≤ s/2`. 이 상한이
이 트레이드오프 전체를 정당화한다 — 오차는 정수 한 단계의 절반을 넘을 수
없고, 비트를 더할수록 단계 `s`는 작아진다(`q_max`가 커지면 ⇒ `s`가 작아진다).
FP16 → INT8 → INT4로 가면 `q_max`가 작아지므로 `s`는 커지고, 그래서 오차
상한이 커진다 — 비트가 적을수록 격자가 거칠어지고 반올림이 커진다. 이것이
아낀 메모리에 대해 치르는 비용이다.

**구체적인 예 (INT4, `b = 4`).** 네 개짜리 숫자 그룹
`x = [0.2, −1.3, 3.1, 0.05]`를 4비트 코드(`q_max = 7`)로 양자화한다.

1. **스케일.** 가장 큰 크기는 `M = max(|0.2|, |−1.3|, |3.1|, |0.05|) = 3.1`이다.
   그래서 `s = M / q_max = 3.1 / 7 ≈ 0.4429`. 이제 정수 한 단계는 대략
   `0.4429`의 값을 갖는다 — 이것이 `1`이 *아님*을 주목하라. 즉 코드와
   실제 값은 진짜로 다르다.

2. **코드** (`q = round(x / s)`):
   - `0.2 / 0.4429 = 0.452 → 반올림 → 0`
   - `−1.3 / 0.4429 = −2.936 → 반올림 → −3`
   - `3.1 / 0.4429 = 7.000 → 반올림 → 7`  *(설계대로 최댓값이 정확히 `q_max`에 안착)*
   - `0.05 / 0.4429 = 0.113 → 반올림 → 0`

   그래서 이 그룹은 정수 코드 `[0, −3, 7, 0]`와 하나의 공유된 스케일
   `0.4429`로 저장된다.

3. **역양자화** (`x̂ = q × s`):
   - `0 × 0.4429 = 0.000`
   - `−3 × 0.4429 = −1.329`
   - `7 × 0.4429 = 3.100`
   - `0 × 0.4429 = 0.000`

   복원된 그룹: `[0.000, −1.329, 3.100, 0.000]`.

4. **오차** (`x̂ − x`):
   - `0.000 − 0.2  = −0.200`
   - `−1.329 − (−1.3) = −0.029`
   - `3.100 − 3.1  =  0.000`
   - `0.000 − 0.05 = −0.050`

   모든 오차는 `|x̂ − x| ≤ s/2 = 0.4429 / 2 ≈ 0.221`이라는 한계를 지킨다.
   여기서 가장 큰 오차는 값 `0.2`에서 발생한 `0.200`으로, 한계를 살짝 밑돈다.
   실패 양상을 주목하자: 작은 값들(`0.2`, `0.05`)은 둘 다 코드 `0`으로
   무너져 자신의 정체성을 잃는 반면, 큰 값 `3.1`은 정확히 포착된다. INT4는
   거친 격자다. 같은 그룹을 INT8(`q_max = 127`, `s ≈ 0.0244`)로 양자화하면
   이 작은 값들도 각자 고유한 코드를 얻어 모든 오차가 대략 18배 줄어들
   것이다. 이것이 "비트가 많을수록 오차가 적다"는 말이 눈에 보이는
   의미다.

**비대칭 양자화(제로 포인트).** 위의 대칭 방식은 실제 값이 한쪽으로
치우쳐 있을 때 — 예를 들어 음수를 `0`으로 잘라내는 함수의 출력처럼 모두
양수인 경우 — 코드의 절반을 낭비한다. 이때는 `−7 … −1` 쪽 절반 전체가
쓰이지 않는다. 이 문제는 실수 `0`을 나타내는 정수 코드인 **제로 포인트
(zero-point)** `z`라는 두 번째 저장 숫자를 추가해 해결한다. 그러면
`q = round(x / s) + z`이고 `x̂ = (q − z) × s`가 된다. 이제 스케일은 전체
범위로부터 만들어진다: `s = (max(x) − min(x)) / (2^b − 1)`. `z`는 격자를
이동시켜 0을 중심으로 강제되는 대신 실제 데이터를 감싸도록 만든다. 대칭
양자화는 그저 `z = 0`인 특수한 경우일 뿐이다. 비용은 값마다 뺄셈 연산이
하나 더 필요하다는 것(여전히 [[arithmetic]])과 `z`를 저장해야 한다는 것이다.

**세밀도(간단히).** 스케일 `s`는 값들의 한 *그룹*에 걸쳐 공유되는데, 그
그룹의 크기가 얼마인지는 선택의 문제다. **텐서 단위(per-tensor)** 양자화는
가중치 행렬 전체에 대해 하나의 `s`를 쓴다 — 저장 비용은 가장 저렴하지만,
큰 이상치(outlier) 하나가 `M`을 부풀려서 다른 모든 값을 거칠게 만든다(만약
우리 예제에 우연히 `30.0`이라는 값이 섞여 있었다면, 스케일은 `≈ 4.3`으로
뛰어올랐을 것이고 `0.2`, `−1.3`은 *모두* `0`으로 반올림되었을 것이다).
**채널 단위(per-channel)** 또는 **그룹 단위(per-group)** 양자화는 텐서의
각 행, 열, 또는 작은 블록마다 자신만의 `s`를 부여하여, 국소적인 이상치가
자기 근방만 거칠게 만들도록 제한한다. 세밀도가 높아질수록 저장해야 할
스케일은 늘어나지만 오차는 작아진다 — 스케일 자체에 적용된, 똑같은
비트-대-오차 트레이드오프다.
