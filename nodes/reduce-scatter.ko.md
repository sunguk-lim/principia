# 리듀스-스캐터

## 요약

**리듀스-스캐터(reduce-scatter)**는 **[[reduce]] 다음에 [[scatter]]**가 이어지는
연산이다: 모든 프로세스가 동일한 길이의 벡터를 하나씩 가지고 있고, 그 벡터들은
**원소별로 리듀스**되며(모든 프로세스의 `j`번째 조각이 하나의 값으로 결합된다),
그런 다음 그렇게 리듀스된 조각들이 각 프로세스가 **하나씩만** 가지도록
**스캐터**된다. 프로세스 `j`는 모든 프로세스의 `j`번째 원소에 대한 리듀스 결과를
가지고 끝난다. 이는 계산과 분할을 *동시에* 수행한다 — 어떤 프로세스도 리듀스된
벡터 전체를 갖지 않는다.

## 상세 설명

[[reduce]]가 **스칼라들**을 하나의 스칼라로 접어 루트에 두는 반면, 리듀스-스캐터는
**벡터들**을 접어서 그 답을 흩뿌린다:

1. **리듀스 부분 — 원소별로, 조각마다.** 프로세스들의 벡터를 하나의 행렬처럼
   나란히 늘어놓는다(행 = 프로세스, 열 = 조각). 각 열 `j`에 대해, 그 값들을
   [[reduction-operation]]으로 결합한다 — [[reduce]]와 똑같지만 각 열마다 한 번씩
   수행하는 것이다. 그림에서 열 0은 `1+5+2+4 = 12`, 열 1은 `2+3+7+1 = 13`을
   내놓는 식이며, 각각은 호박색의 *계산된* 결과다.
2. **스캐터 부분 — 각자 조각 하나씩.** 그렇게 리듀스된 값들은 벡터
   `[12, 13, 10, 15]`를 이룬다. 이를 하나의 루트에 남겨 두는 대신 **스캐터**한다:
   조각 `j`는 오직 프로세스 `j`에게만 간다(`P0=12, P1=13, P2=10, P3=15`) — 이는
   정확히 [[scatter]]의 프로세스당 조각 하나라는 모양이다.

기억해 둘 관계는 다음과 같다: **all-reduce = 리듀스-스캐터 + all-gather**.
all-reduce는 모든 프로세스에게 리듀스된 벡터 *전체*를 준다. 리듀스-스캐터는 그
절반만 한다 — 리듀스는 하지만, 전체 결과를 브로드캐스트하는 대신 **프로세스당
조각 하나씩만** 나누어 준다. 이것이 바로 빠른 all-reduce 구현이 문자 그대로
리듀스-스캐터 다음에 all-gather를 이어붙인 형태로 만들어지는 이유다: 각 단계는
데이터의 `1/n`만 이동시킨다.
