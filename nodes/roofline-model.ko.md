# 루프라인 모델

## 의미

루프라인 모델(roofline model)은 산술과 데이터 이동을 결합해 성능의 상한을 나타낸다. 명시된 연산 집계와 하드웨어 가정에 따른 상한 모형이지 실제 작업이 그 상한에 도달하거나 낮은 연산 집약도의 모든 작업이 메모리 대역폭을 포화시킨다는 증명이 아니다.

## 동작 원리

W를 부동소수점 연산 수, D를 특정 메모리 계층에서 전송한 바이트 수라 하자. I=W/D는 바이트당 연산 수인 [[arithmetic-intensity]]다. P는 이 집계와 호환되는 초당 연산 상한, B는 해당 계층의 초당 전송 바이트 수다. 연산률 R의 모형상 한계는 다음과 같다.

$$R \leq \min(P, B I).$$

왜 최솟값인가? W번의 연산에는 최소 W/P초의 산술 자원이, D바이트 이동에는 최소 D/B초가 필요하다. 완벽하게 겹쳐 실행하더라도 경과 시간은 두 요구량 중 큰 값보다 작을 수 없다. W를 이 시간으로 나누면 두 연산률 상한 중 작은 값이 나온다. I=P/B에서 두 한계가 만나는 능선이 생긴다.

[[memory-hierarchy]] 때문에 측정 계층이 중요하다. 캐시 루프라인에는 해당 캐시의 트래픽과 대역폭을, 주 메모리 루프라인에는 주 메모리 트래픽을 써야 한다. 이상적 알고리즘 바이트 수, 캐시 대역폭, 무관한 실측 연산 수를 섞지 않는다. 숫자 형식, 스칼라/행렬 연산, 희소성, 곱셈-덧셈을 두 연산으로 세는지 여부도 상한과 맞아야 한다.

## 구체 사례

가상의 P=초당 100조 연산, B=초당 3조 바이트를 잡자. 능선은 100/3, 약 33.3연산/바이트다. 원소별 덧셈은 4바이트 값 두 개를 읽고 하나를 써서 12바이트당 연산 하나이므로 I=1/12다. 대역폭 상한은 초당 3조/12 = 0.25조 연산이다.

n=4096인 정사각 행렬 곱에 약 2*n^3번의 연산과 4바이트 n*n 배열 세 개를 한 번씩 읽거나 쓰는 이상적 이동량을 가정하자. 집약도는 2*n^3/(12*n^2)=n/6, 약 682.7연산/바이트다. 모형상 상한은 초당 100조인 산술 지붕이다. 두 지붕의 400배 차이는 서로 다른 연산의 연산률 상한 비교이지 프로그램 실행시간이나 실측 가속 비율이 아니다.

덧셈 실측값이 초당 0.05조 연산이라면 0.25조 상한보다 다섯 배 낮다. 병렬성 부족, 작은 문제 크기, 시작 비용, 접근 패턴, 의존성, 측정 범위 등 원인을 더 찾아야 한다. 그래프의 가로 위치만으로 메모리를 빠르게 바꾸면 충분하다고 증명할 수 없다.

## 검증과 대안

실측 작업과 트래픽을 일치시키고 형식별 연산 상한, 장치와 접근 패턴에 적합한 유지 대역폭을 사용한다. 집약도만으로 병목을 단정하지 말고 실제 대역폭, 명령 발행, 정체, 상주 활용을 살핀다. 낮은 집약도는 융합이나 지역성으로, 높은 집약도인데 상한에 못 미치는 작업은 더 나은 타일링이나 병렬성으로 개선될 수 있다. 해당 커널이 전체 애플리케이션 시간에서 중요한지도 별도로 측정한다.
