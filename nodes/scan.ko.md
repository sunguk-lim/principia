# 스캔 (접두)

## 요약

**스캔(scan)**(포함적 접두 스캔, inclusive prefix scan)은 모든 프로세스가 값을
하나씩 제공하고 프로세스 `i`가 값 `0 … i`의 **[[reduction-operation]]** 결과 —
즉 **누적 합계** — 를 받는 [[collective-operation]]이다. reduce가 최종 답을
하나만 만들어내는 것과 달리, 스캔은 *그 과정에서 나오는 모든 부분 답*을
만들어낸다: 각 랭크는 자기 자신까지 포함한 모든 랭크의 환산 결과를 받는다.

![Scan: values 3,5,2,7 become prefix sums 3, 8, 10, 17 across P0..P3](scan.svg)

## 상세 설명

스캔은 한꺼번에가 아니라 **누적적으로** 적용되는 [[reduction-operation]]이다:

1. **시작 상태.** 각 랭크가 값을 하나씩 가지고 있다 — 그림에서는 `3, 5, 2, 7`.
2. **연산.** 모든 랭크가 동일한 연산 `⊕`로 스캔을 호출한다. 랭크 `i`의 결과는
   `v0 ⊕ v1 ⊕ … ⊕ vi` — 즉 **`i`까지의 랭크들만**을 환산한 값이다. 그림 속
   삼각형 모양의 부채꼴은 이 의존관계를 보여준다: `P0`은 `{0}`에서, `P1`은
   `{0,1}`에서, `P2`는 `{0,1,2}`에서, `P3`는 `{0,1,2,3}`에서 값을 끌어온다.
3. **종료 상태.** 결과는 접두사들의 계단 모양을 이룬다: `P0=3`, `P1=3+5=8`,
   `P2=3+5+2=10`, `P3=3+5+2+7=17`. (오직 루트만 하나의 값을 갖는 reduce와
   달리) 모든 랭크가 *서로 다른* 값을 가진다. `P0`의 접두사는 자기 자신의
   입력값 그대로이므로 변하지 않는다(자신의 데이터 색으로 그려진다). 나머지는
   *계산된* 것이므로 호박색이다.

reduce와의 명확한 대조는 다음과 같다: reduce는 한 프로세스에서 **오직 최종
합계**(`17`)만을 주지만, 스캔은 **모든 중간 합계**를 프로세스마다 하나씩 준다 —
그 마지막 값이 reduce의 답과 같다. 스캔은 [[reduction-operation]]의 동일한
결합법칙에 의존하며, 이 법칙은 또한 접두사들을 엄격하게 왼쪽에서 오른쪽으로
계산하는 대신 (접두합 트리를 통해) 병렬로 계산할 수 있게 해준다.
