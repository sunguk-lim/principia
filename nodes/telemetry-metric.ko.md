# 텔레메트리 메트릭

## 요약

**텔레메트리 메트릭(telemetry metric)**은 반복되는 런타임 [[measurement]] 값을 이름
있는 시계열이나 집계로 바꾼다. “요청이 몇 개 끝났는가?”, “현재 메모리를 얼마나 쓰는가?”,
“요청 지속 시간이 어떻게 분포하는가?” 같은 수량 질문에 답한다.

## 상세 설명

대표적인 세 계측기 모양은 서로 다른 사실을 보존한다. 카운터(counter)는 완료 요청
412개처럼 감소하지 않는 누계를 쌓는다. 게이지(gauge)는 활성 요청 7개처럼 현재 값을
보고한다. 히스토그램(histogram)은 많은 관찰을 구간별로 묶어 모든 요청을 저장하지 않고
분포 요약을 보존한다.

요청 지속 시간 [[measurement]] 값이 80, 120, 230, 900ms라고 하자. 구간을 `≤100`,
`≤250`, `>250`으로 잡으면 개수는 1, 2, 1이다. 전체 개수 4와 합계 1330ms도 보존할
수 있다. 평균은 332.5ms지만 구간은 평균이 숨기는 사실, 즉 한 요청이 나머지 셋보다
훨씬 느렸다는 점을 보여 준다.

메트릭은 세부 정보를 줄이는 대신 비용을 제한한다. 각 요청을 별도 이력으로 저장하면
트래픽에 따라 데이터가 커지지만, 카운터나 고정된 히스토그램 구간 갱신은 저장·질의 작업을
작게 유지한다. `method=POST` 같은 속성으로 시계열을 나눌 수 있지만, 고유 속성 조합마다
상태가 필요하므로 사용자 ID처럼 끝없이 늘어나는 값은 위험한 카디널리티를 만든다.
