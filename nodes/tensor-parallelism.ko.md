# 텐서 병렬성

## 요약

**텐서 병렬성(tensor parallelism)**은 하나의 레이어가 갖는 **가중치 행렬을
여러 GPU에 나누어** 놓음으로써, 한 장치에 담기에는 너무 큰 하나의
[[matrix-multiplication]]을 여러 개의 더 작은 병렬 연산으로 쪼개서 계산하는
기법이다. 데이터 병렬성(전체 [[neural-network]]을 복제하고 *데이터*를
나누는 방식)과 달리, 텐서 병렬성은 *모델*을 나눈다 — 각 GPU는 각 가중치의
샤드(shard) 하나만 갖는다. 샤드는 부분 결과들을 단 한 번의
[[all-reduce]]로 다시 합칠 수 있도록 선택된다.

![텐서 병렬성: 가중치 A는 열로, B는 행으로 나뉘고, 각 GPU가 부분 Z를 계산한 뒤 all-reduce로 합쳐 진짜 Z를 얻는다](tensor-parallelism.svg)

## 상세 설명

[[neural-network]]의 MLP 블록 하나를 생각해보자: `Z = GeLU(X · A) · B`이며,
여기서 `X · A`와 `(…) · B`는 [[matrix-multiplication]]이다. 핵심은 두
가중치를 *어떻게* 샤딩하느냐다:

1. **A는 열로 나눈다.** 각 GPU에 세로 조각 `Aᵢ`(예: A의 출력 열의 1/4)를
   나눠준다. `X`는 복제되어 있으므로, GPU $i$는 `Yᵢ = X · Aᵢ` —
   출력 차원의 한 조각 — 을 계산한다. 통신이 전혀 필요 없으며, **GeLU는
   원소별(element-wise) 연산**이므로 `GeLU(Yᵢ)` 역시 로컬에서 계산된다.
2. **B는 행으로 나눈다** — A의 열 분할에 맞춰서다. GPU $i$는 자신이 갖고
   있는 `Yᵢ`의 열에 대응하는 행 `Bᵢ`를 보유하며, `Zᵢ = GeLU(Yᵢ) · Bᵢ`를
   계산한다. [[matrix-multiplication]]의 규칙(공유 차원에 대해 합산)에
   따라, 각 `Zᵢ`는 출력 형태 전체를 갖지만 **부분합**일 뿐이다 — 축약되는
   차원 중 *자기 몫*만 커버한다.
3. **한 번의 all-reduce로 마무리한다.** 참값은 `Z = Z₀ + Z₁ + Z₂ + Z₃`다.
   서로 다른 프로세스에 있는 값들을 더하는 것이 바로 [[all-reduce]](SUM
   연산)이며, 이를 거치면 모든 GPU가 올바른 `Z`를 갖게 된다. 열 분할 다음
   행 분할이라는 순서는 블록당 **단 한 번**의 all-reduce만 필요하도록
   의도적으로 선택된 것이다.

따라서 텐서 병렬성은 데이터 병렬성과 정반대 방식으로 메모리와 통신을
맞바꾼다. 데이터 병렬성은 모델을 복제하고 **배치**를 나누며, **스텝당**
한 번 **그래디언트**를 all-reduce한다. 텐서 병렬성은 **가중치**를 나누고
**입력**을 복제하며, **레이어당**(순전파마다) 한 번 **활성값**을
all-reduce한다. 이는 가중치가 GPU 한 장에 다 들어가지 않는 레이어조차
아예 돌아갈 수 있게 해준다 — 대신 빈번한 통신이 필요하므로, 보통은 한
노드 안의 빠른 인터커넥트로 연결된 GPU들로 범위가 한정된다.
