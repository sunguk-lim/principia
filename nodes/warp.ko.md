# 워프

## 의미

워프(warp)는 [[streaming-multiprocessor]]에서 CUDA 스레드 32개를 단일 명령·다중 스레드(SIMT) 실행 단위로 묶는다. 각 스레드는 자기 상태와 논리적 레인 번호를 갖는다. 명령에는 활성 레인 마스크가 적용되므로 모든 스레드가 항상 참여하는 것은 아니다. 32개 스레드가 모든 명령을 물리적으로 같은 클럭 사이클에 실행한다는 보장이 아니다.

## 동작 원리

같은 제어 경로를 따르는 스레드들은 명령 발행을 공유하면서 각자 자기 값에 연산을 적용할 수 있다. 분기 때문에 경로가 갈리면 해당 명령들은 서로 다른 마스크로 실행된다. 이런 발산은 발행된 명령당 유효 작업량을 줄일 수 있다. 하지만 경로 길이, 조건부 실행으로의 컴파일, 명령 처리량, 메모리 대기, 다른 준비된 워프 때문에 항상 두 배 느려진다고 결론낼 수는 없다. 비활성 레인은 그 명령의 논리적 연산을 하지 않으며, 이것으로 구체적인 전기적 동작까지 추론해서는 안 된다.

NVIDIA 계산 능력 7.0 미만 장치에서는 워프가 프로그램 카운터 하나와 활성 마스크를 공유했다. 7.0부터는 독립적 스레드 스케줄링이 스레드별 실행 상태를 유지하고 워프보다 작은 단위의 발산과 재합류를 허용한다. SIMT 묶음은 여전히 중요하지만 스레드 간 데이터 교환에서 암묵적 락스텝을 가정한 코드는 틀릴 수 있다. 실제 협력 스레드에 맞는 문서화된 동기화와 참여 마스크를 사용한다. 같은 워프 소속이라는 사실만으로 메모리 순서나 데이터 가시성이 보장되지 않는다.

## 구체 사례

레인 0–31 중 16 미만은 경로 A, 나머지는 B로 보낸다. A에 추상적 발행 단계 4개, B에 12개가 있고 겹침이나 정체 없이 마스킹된 경로를 직렬 실행한다고 가정하자. 단계 4개에서는 앞의 16개 레인이, 단계 12개에서는 뒤의 16개가 활성이다. 유효 레인-단계는 16*4 + 16*12 = 256이고 전체 자리는 32*(4+12) = 512이므로 이 모형의 유효 참여율은 50%다.

이는 활용도 계산이지 실행시간 벤치마크가 아니다. 기준 대안도 없이 실행시간이 두 배라고 증명하지 않는다. 입력을 재배열해 워프 전체가 같은 경로를 따르게 하면 명령 발행이 달라질 수 있지만 이동 비용, 지역성, 스케줄링도 변한다. 비용 없이 불이익이 없어진다고 하지 말고 측정한다.

## 검증과 대안

균일한 입력과 분기 많은 입력, 짧고 긴 경로, 끝부분 그룹, 실제 대상 아키텍처를 시험한다. 스레드 간 통신에서는 한 번 관측된 락스텝 대신 동기화의 마스크와 메모리 순서 계약을 확인한다. 명령 발행, 활성 참여, 정체와 전체 커널 시간을 함께 측정한다. 유사 작업 묶기, 조건부 실행, 다른 분해 방식을 비교하고 재배열 비용이 더 크면 기존 분기를 유지한다.

## 이해 확인

같은 워프의 두 스레드라면 동기화 없이 데이터를 교환해도 안전한가? 일반적으로 아니다. 아키텍처, 참여 스레드, 문서화된 동기화 계약이 중요하다.
