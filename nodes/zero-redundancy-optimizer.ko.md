# Zero Redundancy Optimizer

## 의미

ZeRO는 완전한 [[data-parallelism]] 복제본을 사용하는 작업자들 사이에서 중복된 모델 상태 저장을 줄인다. 옵티마이저 상태, 그래디언트, 매개변수를 단계적으로 분할한다. 작업자는 분할된 상태의 자기 몫만 소유하고, 계산에 필요한 값은 통신으로 확보한다. 핵심은 저장 소유권이며, 모든 계층의 산술 연산을 작은 텐서 연산으로 나누는 것은 아니다.

## 작동 원리

분할하지 않은 모델 하나의 영구적 바이트 총량을 세 부분으로 나누자. W는 계산용 매개변수, G는 그래디언트, O는 마스터 매개변수 사본을 포함한 옵티마이저 관련 상태다. N은 같은 크기의 작업자 수다. 패딩, 임시 재구성과 통신 버퍼를 제외하면 작업자당 영구적 상태는 다음과 같다.

| 방식 | 작업자당 영구적 모델 상태 바이트 |
| --- | --- |
| 완전 복제 | W + G + O |
| ZeRO 1단계 | W + G + O/N |
| ZeRO 2단계 | W + G/N + O/N |
| ZeRO 3단계 | (W + G + O)/N |

1단계는 옵티마이저 상태를 분할하고 소유한 매개변수를 갱신한다. 2단계는 리듀스된 그래디언트도 분할한다. 3단계는 계산용 매개변수까지 분할하고 순전파와 역전파 계산 전후에 필요한 매개변수 그룹을 모은다. [[gather]] 원리는 분산된 조각을 재구성하는 이유를 설명한다. 실제 통신량과 임시 메모리는 구현의 집합 통신 일정, 그룹 크기와 중첩 방식에 따라 달라진다.

이 식은 모델 상태의 크기이지 장치 최대 메모리의 보장이 아니다. [[training-memory-budget]]에는 유지하는 활성값, 임시 작업 공간, 미리 가져온 매개변수 그룹과 집합 통신 버퍼도 포함된다. 영구적 저장은 분할되어 있어도 실행 중에는 완전한 매개변수 그룹 일부가 존재할 수 있다. 균등 분할은 이상화이며, 불균등한 그룹, 패딩, 정밀도와 유지 정책이 실제 할당을 바꾼다.

## 예시

M을 10억 개의 매개변수라고 하자. 계산용 FP16 가중치는 2M바이트, FP16 그래디언트는 2M바이트, 옵티마이저 관련 상태는 12M바이트라고 명시적으로 가정한다. 마지막 항은 FP32 마스터 사본의 4M과 FP32 Adam 모멘트 배열 두 개의 8M을 합한 것이다. 십진 단위로 W=2GB, G=2GB, O=12GB이며, 완전히 복제한 영구적 상태는 16GB다. N=4일 때 다음과 같다.

- 1단계: 2 + 2 + 12/4 = 작업자당 7GB.
- 2단계: 2 + 2/4 + 12/4 = 5.5GB.
- 3단계: (2 + 2 + 12)/4 = 4GB.

각 텐서의 실제 자료형으로부터 상태 크기를 계산했다. 그래디언트가 FP32라면 G가 4GB가 되므로 관련 총량도 달라진다. 별도 마스터 사본이 없는 프레임워크에서는 O도 다르다. 영구적 상태가 4GB라는 이유로 4GB 장치에서 3단계를 실행할 수 있는 것은 아니다. 활성값과 재구성한 그룹에도 공간이 필요하다.

## 경계와 검증

완전 샤딩 데이터 병렬 구현은 3단계와 분할 후 재구성하는 큰 원리를 공유하지만, 제품 API, 집합 통신 일정과 메모리 수명까지 같은 계약은 아니다. 텐서 및 파이프라인 분할은 계산을 다른 방식으로 나누며 상태 샤딩과 함께 사용할 수 있다. 호스트나 저장 장치로의 오프로딩은 장치 저장을 N으로 나누는 것과 달리 상태 일부를 다른 메모리 계층으로 이동한다.

모델, 정밀도, 유효 배치와 옵티마이저 목적을 고정하고 최대 할당 및 예약 장치 바이트, 통신량, 학습 단계 시간과 정한 수치 허용 오차 안에서의 갱신 일치성을 측정하라. 가장 큰 임시 재구성과 활성값 피크를 확인하라. 깊은 샤딩으로 더 큰 모델을 수용해도 제한된 인터커넥트에서는 느려질 수 있다. 저장 절감만으로 속도 향상을 입증할 수 없다.

## 이해 확인

**질문:** 옵티마이저 상태는 항상 FP16 계산용 가중치 바이트의 두 배인가? **답:** 아니다. 여기서 명시한 마스터 사본과 두 모멘트 배열 정책에서는 여섯 배다. 실제 비율은 정밀도와 옵티마이저 선택에 달려 있다.
