# 제로 중복 옵티마이저

## 요약

**제로 중복 옵티마이저**(Zero Redundancy Optimizer, ZeRO)는 평범한
[[data-parallelism]]에 내재된 낭비적인 **중복(replication)**을 제거한다. 평범한
데이터 병렬 처리는 모든 워커에 세 가지의 *전체 사본*을 유지한다: 모델
**파라미터**(학습된 수치들), **그래디언트**(각 스텝마다 생성되는 파라미터당 하나의
조정값), 그리고 **옵티마이저 상태**(업데이트 규칙이 스텝 사이에 유지하는 파라미터당
부가 부기 정보)이다. 이 세 가지 모두를 모든 GPU에 유지하는 것은 대단히 중복적이다.
ZeRO는 대신 이들을 **샤딩(shard)**한다 — 각각을 N개의 동일한 조각으로 잘라 N개의
워커 각각에게 하나의 조각만 준다 — 그리고 필요한 순간에만 하나의 조각을
**[[gather]]**해온다. 이를 세 단계로 점차 강화하여 수행하는데, 각 단계는 통신을
더 많이 요구하는 대가로 GPU당 메모리를 더 절약하므로, 데이터 병렬 처리의 단순한
"배치를 나눈다"는 구조를 유지하면서도 GPU 한 대의 메모리보다 훨씬 큰 모델을 학습할
수 있다.

## 상세 설명

[[data-parallelism]]이 무엇을 저장하는지 다시 떠올려보자. 모든 GPU는 *동일한*
전체 모델을 유지하고, 각 스텝마다 자신의 배치 조각으로부터 그래디언트를 계산한
다음, GPU들 사이에서 그래디언트를 평균하여 모든 복제본이 동일한 업데이트를
적용하고 동기 상태를 유지한다. 이를 위해 각 GPU는 다음의 완전한 사본을 유지해야
한다: **파라미터** `P` (바이트 단위 크기도 `P`라고 부르자), **그래디언트**(파라미터와
개수가 같으므로 또 다른 `P` 바이트), 그리고 **옵티마이저 상태**. 옵티마이저
상태는 사람들이 과소평가하는 부분이다. 단순한 업데이트라면 스텝 사이에 아무것도
유지하지 않고 `weight ← weight − learning_rate · gradient`만 하면 된다. 하지만
널리 쓰이는 Adam 업데이트는 *파라미터당* 그래디언트의 이동 평균과 그래디언트
제곱의 이동 평균 — 각각 추가 수치 두 개 — 그리고 가중치의 고정밀도 마스터 사본까지
유지한다. 흔히 쓰는 혼합 정밀도(mixed-precision) 설정에서는 이것이 약 `2P` 바이트의
옵티마이저 상태로 합산된다. 즉 파라미터 메모리의 약 *두 배*이다. 따라서 평범한
데이터 병렬 처리는 GPU당 모델에 대해 약 `P + P + 2P = 4P` 바이트를 소비하며,
**이 동일한 `4P`가 N개의 GPU 각각에서 반복**된다. 이 반복이 바로 ZeRO라는 이름이
가리키는 "중복(redundancy)"이다.

**핵심 아이디어.** 이 세 가지 중 어느 것도 *항상 전체가* 필요하지는 않다.
파라미터는 그 레이어가 실행될 때만 참조되고, 그래디언트는 옵티마이저가 그
파라미터를 업데이트하는 순간에만 중요하며, 옵티마이저 상태는 바로 그 업데이트
동안에만 다루어진다. 따라서 모든 GPU가 세 배열 전체를 저장하는 대신, ZeRO는
각 GPU에 **각 배열의 1/N에 대한 소유권**을 부여하고 필요할 때마다 전체 조각을
재구성한다: 사용 직전에 소유자로부터 필요한 슬라이스를 모아온(gather) 뒤, 모아온
사본을 버리고 상주하는 1/N 몫으로 되돌아간다. 스텝의 결과는 평범한 데이터
병렬 처리와 수학적으로 동일하다 — 동일하게 평균화된 업데이트가 동일한 가중치에
도달한다 — 다만 어떤 GPU도 세 배열 전체를 한꺼번에 보유하지 않는다는 점이 다르다.

**세 단계, 각각 배열 하나씩 더 샤딩한다.** ZeRO는 각 배열을 독립적으로 샤딩할 수
있고, 더 많이 샤딩할수록 메모리는 더 절약되지만 네트워크로 이동하는 데이터는
더 많아지기 때문에, 점점 강화되는 수준으로 제공된다.

- **1단계**는 **옵티마이저 상태**만 샤딩한다. 이것이 (위의 `2P`처럼) 가장 큰
  단일 블록이므로, 그 중복을 제거하는 것이 가장 적은 통신 추가로 가장 큰 단일
  절약을 얻는다. 각 GPU는 전체 파라미터와 전체 그래디언트를 유지하지만
  옵티마이저 상태의 `2P/N`만 소유하여, 자신의 1/N에 해당하는 가중치만 업데이트한
  뒤 업데이트된 슬라이스를 공유한다.
- **2단계**는 추가로 **그래디언트**를 샤딩한다. GPU는 자신이 업데이트할
  파라미터에 대해서만 전체 그래디언트가 필요하므로, 그래디언트의 `P/N`만
  유지하고 각 그래디언트 슬라이스가 모든 곳에 보관되는 대신 그 소유자에게로
  합산되도록 한다.
- **3단계**는 추가로 **파라미터 자체**를 샤딩한다. 이제 GPU는 영구적으로
  가중치의 `P/N`만 보유하며, 어떤 레이어가 계산을 수행하기 직전에 그 레이어의
  전체 가중치를 모아와야 하고 그 이후에는 버려야 한다. 이 가장 깊은 단계는
  Fully Sharded Data Parallel(FSDP)이라고도 알려진 방식과 정확히 같다: 세
  배열 모두를 샤딩하는 동일한 아이디어이다. (모델이 너무 커서 맞지 않을 때
  워커들 사이에서 파라미터를 샤딩하는 것은, *하나의* 레이어의 연산을 여러
  GPU로 나누는 텐서 병렬 처리나 파이프라인 병렬 처리와는 다르다. ZeRO는 각
  레이어의 연산은 그대로 유지한 채 오직 *저장소*만 분산시킨다.)

**구체적 사례.** 파라미터가 `P` 바이트를 차지하는 모델을, Adam으로 GPU `N = 8`대에서
학습한다고 하자. 평범한 [[data-parallelism]]은 GPU당 비용이
`P (파라미터) + P (그래디언트) + 2P (옵티마이저) = 4P`이다. 단계를 적용하여
샤딩되는 배열만 `N = 8`로 나누어 보면:

- **1단계** (옵티마이저 샤딩): GPU당 `P + P + 2P/8 = P + P + 0.25P = 2.25P`.
- **2단계** (그래디언트도 샤딩): `P + P/8 + 2P/8 = P + 0.125P + 0.25P = 1.375P`.
- **3단계** (파라미터도 샤딩): `P/8 + P/8 + 2P/8 = 4P/8 = 0.5P`.

따라서 3단계는 원래의 `4P`를 `4P/N = 0.5P`로 바꾼다 — `N = 8`에서 GPU당 모델
메모리가 8배 감소한 것이다. 구체적으로, 파라미터·그래디언트·Adam 상태를 위해
GPU 한 대에서 1.2TB가 필요했을 모델(어떤 단일 장치도 감당할 수 없는 크기)이
3단계 아래에서는 GPU당 약 150GB에 들어맞아 이제 실현 가능해진다. 대가는
통신이다: 단계가 깊어질수록 사용 전에 조각을 모아와야 하고 사용 후에 다시
샤딩해야 하는 빈도가 늘어나므로, 메모리 절약은 매 스텝 네트워크를 오가는
추가 데이터로 지불된다 — 이것이 ZeRO가 조절할 수 있게 해주는 핵심 트레이드오프이다.
